# 原生 UI 脱机自检与反“用户截屏测试员”原则 (UI Visual Self-Inspection)

在修改、重构或新增任何 UI 界面、组件、面板、列表、卡片或徽标时，必须严格遵守以下三大铁律，严禁要求用户启动游戏截屏充当“视觉测试员”：

## 1. 强制脱机原生渲染自审 (Mandatory Offline OpenGL Inspection)
- **禁止盲猜交付**：严禁在未调用脱机渲染工具生成实际截图前，仅凭 Lua 代码推导就向用户声称“布局已修复/已对齐”；
- **真实渲染回读**：在任何 UI 布局代码修改完成后，必须运行：
  ```powershell
  pwsh -File tools/preview-native-ui.ps1 -Scene <scene> -Smoke -Language <CN/EN> -Width 1280 -Height 800
  ```
  （当前支持场景：`settlement` 据点概览、`squad` 小队HUD、`widgets` 核心组件、`native` 原版面板）；
- **自读截图闭环**：工具运行完成后，必须直接调用 `read_file` 读取生成的真实渲染截图（`preview-rN.png` 或 `latest.png`），在后台亲自以计算机视觉审查布局细节。

## 2. 视觉自审五大关键核对点 (Visual Checklist)
在审查捕获的原生截图时，必须逐项核对并确认：
1. **压字与留白**：图标、齿轮、指示灯或动效外缘与相邻文字起点是否至少保持 10px 安全呼吸间距，严禁图标压字；
2. **穿模与层级截断**：卡片内部的说明文字（如日均消耗、阶段文本）是否完整容纳于卡片内衬，是否与卡片下方的实体按钮或分割线产生位置重叠或被遮挡；
3. **语义与色彩匹配**：货物监管态（如箱内待取 `IN_STORAGE`）与作业调度态（如待认领 `WAITING`）是否清晰分离，是否存在“0 物资却挂着充裕绿标”或“执行中却标注待认领”的荒谬现象；
4. **多语种与文字溢出**：在英文（`EN`）和中文（`CN`）模式下，标签或长按钮文字是否超出父级边界或发生难看的断行；
5. **折叠与展开态对称**：卡片在展开抽屉（Drawer）态下高度计算是否精准闭合（无抽屉缝隙撕裂），折叠态下是否合理透出关键物料微摘要。

## 3. 持续自主迭代，禁止转嫁成本 (Autonomous Remediation)
- 若在截图审查中发现任何瑕疵（如齿轮尺寸超标、间距过紧、文字错位），必须在当前对话中**自主修改代码并重新运行工具验证**，直到视觉完美闭环；
- 自检通过后，方可向用户汇报修改结果，并可将渲染对比截图通过 Artifact 呈现供用户复核，绝不让用户为了排查基础对齐而反复进退游戏。
