- 踩坑结论写入已有专题或证据文档，带版本与出处；不把开发流水和过期行号堆进必读文件。

## 源码与接口

- 游戏目录：D:/Software/GameApp/steam/steamapps/common/ProjectZomboid。
- 优先查安装目录 media/lua 与当前 projectzomboid.jar；旧反编译目录可作导航，关键结论核对 JAR 版本/哈希，必要时重新反编译或 javap。
- 索引、类型桩、旧报告仅作辅助。检索不到先核对覆盖范围、继承和暴露面，不能直接断言 API 不存在。
- Kahlua的标准库声明不等于游戏实际注册的全局表：PZ42.21.0实机已确认next调用为nil，空表判断使用pairs提前退出；限定Kahlua回归也显式不提供next，见[物流修复证据](reviews/2026-10-21/probe-0.15.1-logistics-repair.md)。
- 优先复用原版实现；Lua 引擎调用使用存在性守卫，不用大范围 pcall 掩盖 userdata 接口错误。

## 通用实现约束

- UI遵循在线需求第11节与[当前UI基础契约](ui-architecture.md)：复用组件、相对布局、setState局部更新，关闭释放订阅；通用文案优先原版翻译键，专属键CN/EN成对，不强制中文。中文排版须在实际Kahlua验证，标准Lua替身不能代替；事件驱动不等于原生UI无绘制开销。

- 用户于2026-10-19重申：所有底层架构都须以高性能、高可扩展性和可维护性为设计目标，最大程度降低后续新功能与模组兼容的改动量和理解难度。通过清晰职责、稳定契约、注册扩展、有界低频工作与版本化数据逐项落实；不为假想功能提前构建复杂系统，不以设计目标代替性能实测。

- 用户于2026-10-20明确：多NPC是最终目标；阶段使用单NPC验收不允许把正式任务、载体、调度和资产归属设计为单例。共享业务内核按稳定npcId/taskId隔离，集中仲裁资源、使用全局预算；原单载体探针只作为迁移适配边界，不能直接成为正式多NPC核心。见[决定与建议次序](decisions/2026-10-20-multi-npc-foundation.md)。

- 当前单人由本地世界执行者裁决世界与资产变化；未来MP由服务端裁决，客户端发意图。OnClientCommand 参数为 (module, command, player, args)，player 是第三项。
- 持久化、同步与权限校验是三件事；写入 ModData 不自动获得服务端权威或崩溃一致性。
- 使用目标版本目录、唯一 mod id 和正确加载域；mod.info 与版本目录中的 media 同级。玩家可见字符串走 CN/EN 成对翻译键。
- 避免每帧全量扫描、重复结算和无界重试；性能结论以测量为准。UI 生命周期按当前原版基类契约处理。

- 据点/仓储遵循[读取与权威边界](settlement-storage-architecture.md)：UI读取副本和只读快照，写入走命令；观察者失败不撤销已核对的物理效果；关闭释放盘点请求，跨世界清旧视图。后续生产/贸易必须重验原资产，不直接消费汇总数量。

## 原生交互与玩法验收

- 2026-10-25用户指出反复返工：原生动作修改先核查完整的前置、定位/部件、动画位移、效果、退出与保存链路，关键未知先做最小原型；不以调用了某原版类认定整个流程正确。
- 先定义玩家可观察结果（实际位置、动作连续性、频率、失败回退），再实现和选测试。替身优先验证模块接缝与责任；候选出现、入队、编译或金样本一致不证明原生玩法通过。
- 高风险组合先验证最小闭环再扩展。无法在当前环境运行游戏时，如实记录该验收差额，不把“开发检查通过”写成“玩法已完成”；保留集中交付，避免让用户逐内部切片重复测试。
