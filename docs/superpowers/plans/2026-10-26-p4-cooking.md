# P4 自主厨师 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.
> 本会话按用户“开始吧。基础必须打好”原生顺序执行，不启动子代理；上述执行技能未在当前环境提供，不虚称已调用，不因此重复请求开工授权。

**Goal:** 按全员人口与成品有效饱食度维持共享餐食，厨师自主配料/调味，支持指定成品和完整炉具责任。

**Architecture:** [设计0.4](../specs/2026-10-26-p4-cooking-and-supervision-design.md)，统一Job/Claims/Session和BT；共享配方事实、有界纯计算BOM及原生机制适配，观察、供餐额度、原件、身体与Duty各有清楚边界。不能用新库存账本或独立厨师循环绕开现有公共认领。

**Tech Stack:** PZ42当前固定JAR、Kahlua Lua、现有Java批量读取与原版TimedAction。

**Spec:** [自主厨师详细设计](../specs/2026-10-26-p4-cooking-and-supervision-design.md)。

## Global Constraints

- 全部存活且正式归属NPC持续计入，外出不扣；玩家不自动计入。
- 剩余供餐量使用原版getHungerChange有效值；getHungChange原件消费追踪不混算。
- u=0.15，L=N×u，H=2N×u为当前授权执行的初始值，保留最小合法批次越量边界；只读成品事实，不改食物效果。
- 最多2次不同可选调料，不新增独立寻调料路径；普通电炉、授权有效冷藏；未知不重放。
- 保留另一个AI的全部修改，不重置/清理工作区；不把开发检查当原生玩法验收。

## Review Focus

1. 两厨师同帧额度竞争、已交付食物与在制双算，归Task1/2。
2. 原版加料替换基底/部分消耗/过期回调，归Task3。
3. 同炉争用、玩家介入和接班取消，归Task4。
4. 保存后丢失Claims、未知效果被重试，归Task1/4。
5. 成品不能被现有自理消费或无有效冷藏，归Task2/5。
