# 调度性能改进实施计划

日期：2026-10-24。用户已在本聊天批准实施，主代理当前会话独立执行，保留工作区已有改动，不自动提交混合修改。

**Goal:** 消除公共预检与全员轮转绑定，约束材料匹配实际操作，减少阻塞任务重复计算，并保留唯一认领和恢复协议。

**Architecture:** 遵循[唯一架构](../specs/2026-10-22-npc-behavior-architecture-design.md)及[统一任务协议](../specs/2026-10-23-unified-task-dispatch-design.md)。先建立匹配游标，再以全局有界预检队列独立推进；角色相关谓词不共享，缓存只负责定位与观察，最终Production仍重验原件。附件的预算先行、按需激活、防惊群和低频兜底建议择项吸收；毫秒级最终核验不是未经测量的承诺。

**Tech Stack:** PZ安装Kahlua、Lua、现有Java构建和pz工具链。不新增线程、依赖或寻路预检。

## 约束与接口

- PrecheckQueue.new(limit)、get(id)、put(id,entry)、remove(id)、step(operations,validate,complete,clock)：最多4个角色私有请求，分片8操作，合计128操作/正常tick，软时间上限2ms在片间检查。软时间不能中断同步引擎调用。
- ProductionSupply:step(budget)把匹配边检查、栈推进和结果收集计入预算；保留原返回协议，未结束返回false。
- ProductionChain:step(budget)保留无参32默认值；每次只推进一个阶段，公共队列传8。
- PublicWork继续保存原Order/Job格式，预检状态、冷却和统计均为可重建临时数据；不迁移原件，不取消玩家暂停或未知效果。
- 事件只标记版本；按容器来源及据点筛选失效，8～15秒分散兜底；角色能力失败仅冷却该角色。

## Review Focus

- 重叠材料选择必须可增广重排，预算1也能完成且不重复原件。
- 忙碌/跟随、工种禁用、出据点、保存屏障与世界切换必须取消或阻止对应预检/认领。
- 多NPC竞争同单、提示原因变化不能破坏他人预检，旧就绪结果不能授权资产。
- 缺料时可做搬运，但高优先级制作不能仅因多帧预检而被永远饿死；等待有界。
- 补料惊群只能入队，预算不得随事件数或NPC总数增长。

## Tasks

1. 添加宿主性能/边界夹具，记录旧实现16/32/64人预检推进与开工延迟；只称模拟调度结果。
2. ProductionSupply增量匹配及结果组装，ProductionChain预算透传与阶段让出；先验证预算及制作原件语义。
3. 添加PrecheckQueue公平推进、操作/时间预算和有界统计；PublicWork拆分预检推进与人员决策，限制准入、保留新鲜结果并在认领前重验。
4. 定向失效与失败复验，合并通知、防惊群；接现有共享目录/Provider边界，不为未实现工种建设空框架。
5. 定向回归、preflight、构建/release-check，归档基线与结果，更新HANDOFF/BACKLOG。实机及PZ规模耗时未运行必须保留为未验证。
