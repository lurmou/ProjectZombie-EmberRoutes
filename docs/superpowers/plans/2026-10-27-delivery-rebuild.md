# 仓储配送执行链重构实施计划

**目标：** 在保留仓储入口的前提下，以统一任务与原件责任协议完成可恢复的单人配送。

**架构：** 配送订单和公共候选接入现有派工，配送 Job 通过 TaskRuntime/TaskController 持有身体会话和 LaborStore 的原件声明；玩家为需要单独验证的动态交付目标。玩家移动时不交付，背包放不下时采纳选项 1（等待玩家腾空间）：物品留在配送员身上承担责任，向玩家提示整理背包，待空间充足停稳后继续交付，避免未经玩家选择丢地。

**技术：** PZ B42 Lua/Kahlua、现有 Java 桥和原版动作。**设计：** [配送执行链设计](../specs/2026-10-27-delivery-rebuild-design.md)。

## 全局约束

- 先保留工作区现有改动；参考项目只读。逐项对照 `docs/development-rules.md`、NPC 架构及统一派工设计。
- 不改在线需求，不承诺多人、零损失或未知原生能力。修改 Lua 后按项目规则运行 preflight；Java 修改需构建和相关验证；翻译 CN/EN 配对。适用项目版本递增和版本日志规则。
- 新增玩法或 UI 交互需用户决策。未经真实验证的动作、保存恢复和性能独立标注。

- [x] 追踪 ProjectRemnants 中 NPC 观察僵尸、蹲行控制、玩家与 NPC 转移的完整调用链，并对照当前安装版原版 Lua/JAR；确定有效观察、姿态授权、转移效果和失败语义。不可用或未证实时停止对应原生接线并报告。

## 任务 2：订单及公共派工

**修改候选：** `DeliveryService.lua`、`PublicWork.lua`、`PublicWorkProviders.lua`、订单持久化与恢复相关模块；保留 `PublicWork.createDeliveryOrder(actor,scope,items)` 界面入口。

- [x] 将配送改为稳定订单 ID、scope、请求数量、版本和可持久化状态；不持久保存 actor、item、container userdata；候选可重建。相同订单的执行额度互斥，发布/领取/失败回退通过现有公共协议。
- [x] 利用 hauling 类别及成员权限参与正常择人，不能调用旧独立选人循环。UI 区分已接受、待领和失败；重验库存与权限，重复请求不得重复结算。
- [x] 与现有物流、制作任务竞争同一 NPC 或原件时只能一方成功；无合格工人订单保持等待。

## 任务 3：原件声明、分批和交付

**修改候选：** `HaulAgent.lua`、`HaulManifest.lua`、`LaborStore.lua` 及实际转移动作适配器；若固定终点协议不支持玩家，增加专用业务适配，不另建资源权威。

- [x] 按现有 claims 协议锁定具体原件，确认源容器可访问、原件仍存在，按 NPC 剩余负重分批；无法承载的单件保持阻断并反馈。
- [x] 玩家动态终点在每次交付前验证同层、距离、玩家与原件；使用经核实的原生转移及实际效果回执，逐件结清，不以删除后按类型重建实现转移。
- [x] 玩家移动时不开始交付；逐件复验，玩家重新移动则暂停余下交付。玩家背包放不下时采纳选项 1（等待玩家腾空间）：物品留在配送员身上承担责任，向玩家提示整理空间；玩家腾出空间并重新停稳后继续逐件交付；若玩家超出 50 格或取消订单则走安全返仓。玩家移动、其他人取走物品、转移结果未知均不能重复结算。

## 任务 4：身体控制、追送与蹲行

**修改候选：** 配送行为适配器、`TaskRuntime.lua` 的既有接入点及 NPC 观察/动作模块。

- [x] 经 TaskController 的活动会话取得身体能力；取货、追送、停步、姿态均受会话约束。目标显著变化或寻路失败时有界重规划，停止后确认，不循环重发移动。
- [x] 以据点边界外 50 格为追送上限；超限转入责任收尾。仅据点外且观察到僵尸才蹲行，脱离条件则恢复；危险抢占优先，蹲行与安全判定分离。
- [x] 检验上下层相同坐标不能取货或交付；无路径、玩家移动和僵尸观察失效不会制造虚假到达或姿态状态。

## 任务 5：取消、退库、保存与恢复

**修改候选：** 业务 Job 恢复、`Persistence.lua`、`Boot.lua` 的现有统一生命周期入口；不引入平行保存屏障。

- [x] 超限或取消时停止领取未取原件；已取原件由同一责任人正常送回允许存储点。目标失效或路径不可用时挂起保留声明；确认入库后逐件结清。
- [x] 将死亡、NPC 失效、世界退出、保存/重进和旧回调纳入停稳、效果确认、责任持久化。未知效果保留待核对，拒绝重放；不把 `resetDelivery` 清空内存当安全收尾。
- [ ] 评估旧内存订单和正在携货的现场；无法可靠识别时隔离并报告，不自动删除、不复制、不声称可迁移。

- [x] 覆盖：两单争同一原件；不同任务争同一 NPC；跨楼层；按负重分批；目标移动；玩家超过 50 格；观察到/失去僵尸；携货中断与归还失败；交付未知效果和迟到回调；正常保存重进。报告实际命令与结果，失败不掩盖。
