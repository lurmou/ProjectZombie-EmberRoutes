# Phase 0 专服载体与同步实施关口

> 日期：2026-10-19｜状态：按用户单人优先决定搁置，以下实现未开始

当前执行 [单人优先决定](../../decisions/2026-10-19-sp-first.md)，本计划仅保留为未来适配参考。

**Goal:** 证明一个无真实玩家槽位/伪连接的服务端 NPC 可模拟，并由两个客户端一致显示；覆盖加入、移动、动作与销毁的权威路径。

**Architecture:** 服务端持稳定 NPC ID 与唯一执行权；客户端仅持表现代理。沿用现有 SP 探针作回归基线，不在专服调用当前 ProbeNpc 的普通 super.update 链。先确定可用原生服务器更新入口，再接自定义生命周期/状态同步；动作逐项适配，不把客户端 ISTimedActionQueue 直接搬到专服。

**Tech Stack:** 当前安装 B42.21.0 / ZombieBuddy 2.3.4；Java + Lua。按项目约束顺序实施，不派子代理。

## 已核对的准备条件

- 本机存在 `D:/Software/GameApp/steam/steamapps/common/Project Zomboid Dedicated Server`。
- 其中 `java/projectzomboid.jar` SHA-256 为 `E1A69EB743EDE60B213A0FE7F8B83D4FCAB773036D256CC4543A336F3B058A33`，与已评审客户端游戏 JAR 一致；无需按另一个未知版本推断服务器 API。
- 默认 StartServer64.bat 使用 `java/;java/projectzomboid.jar` 和 headless 启动；所查根目录/java 未见 ZombieBuddy.jar，现有脚本未显式装载它。专服 ZombieBuddy 装载与探针入口仍须实际验证，不能把文件存在当成服务器已就绪。
- 本轮没有启动服务器、修改服务器/游戏安装、调整全局 JVM 参数、开放端口或运行双客户端。
- 已有 [可行性评审](../../reviews/2026-10-18/feasibility-review.md) 中 E31 的服务器更新链和 E09–E11 的动作身份约束，在同一 JAR 基线下仍适用；必须复用正确入口或明确适配，不能仅去掉拒绝分支。
