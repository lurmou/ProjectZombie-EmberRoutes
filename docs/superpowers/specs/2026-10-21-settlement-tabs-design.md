## 现状与方案选择

- `SettlementDashboard.lua` 与 `LogisticsDashboard.lua` 都继承 ISCollapsableWindow，各有独立 opened 引用和服务订阅。目前能同时存在两个窗口，物流的仓储按钮通过关闭/重开跳转。
- WarehouseIndex.watch 会立即回调；最后一个消费者释放时删除该盘点上下文并停止其扫描。重新进入仓储可能需要重新有界盘点，不能宣称切页无重扫。
- LogisticsService.watch 仅负责视图通知，释放后不会停止已经启动的物流业务；初始状态需单独读取 Service.status。
- 当前仓储定位标记有独立 OnRenderTick 回调；切走也应主动 clear，不能只隐藏仓储列表。
- 本机原版 ISTabPanel 的 activateViewById 只切换可见性并调用 onActivateView，不会自动释放本模组的服务订阅。

方案比较：

| 方案 | 取舍 |
|---|---|
| 推荐：单一窗口外壳、两个独立页面 | 提取现有页面，显式管理激活/停用；复用列表与服务，改动集中且便于后续增加真实功能页 |
| 直接嵌套现有两个窗口 | 初始改动较少，但保留两套标题栏、关闭、单例与焦点所有权，生命周期容易冲突 |
| 重写全部界面和数据服务 | 改动面大，增加仓储差分和物流动作回归风险，本切片无此必要 |

## 用户可见行为

一个据点管理窗口，标题显示当前据点，标题下固定“仓储｜物流”页签。沿用 Theme、字体相对尺寸和 Layout，不在本轮重做既有内容的视觉体系。

仓储保留搜索、分类、排序、分页、来源、定位、刷新、范围编辑与帮助；物流保留启停、双模式、工人名单、详情、重试与移除。关闭由外壳统一承担，页内不再重复关闭按钮；原物流仓储跳转改为切到仓储页。

据点管理入口默认仓储；既有物流入口定位同一窗口的物流页，保留快捷路径。相同玩家与据点再次打开时复用窗口并切页；换据点或玩家先彻底关闭旧实例。统一管理本阶段沿用现有全局单窗口边界，不宣称支持本地分屏。

同次打开期间保留仓储搜索/分类/排序/页码/滚动与选择、物流选中工人；新数据到来后按稳定键恢复合法选择。仓储重新盘点期间保留筛选意图，旧数量不作为最新可用量展示。尚未开发的制作、报表等不放空页占位。

## 组件与生命周期

`SettlementDashboard` 作为外壳，只拥有据点/玩家/世界身份、页签、页面工厂、窗口关闭与统一低频有效性检查；仓储与物流内容分别放到 `UI/WarehousePage.lua`、`UI/LogisticsPage.lua`，复用现有 WarehouseControls/Rows/Details/List、LogisticsCards/Presentation 等组件。`LogisticsDashboard.open(actor,id)` 保留为薄兼容入口，转发统一窗口物流页。

页面契约：`activate()` 幂等订阅并读取最新状态；`deactivate()` 先标为不活动、再释放订阅和临时显示资源；`dispose()` 幂等终结生命周期。只在首次访问时创建页面。隐藏页停止状态投影、查询、排版和页面自己的周期检查。外壳不持有仓储盘点订阅。

切页顺序：检查当前世界/玩家/据点访问资格，停用旧页并释放数据订阅、提示框和定位标记，隐藏旧页，再激活新页并设置焦点。订阅可能同步回调并关闭窗口，注册释放句柄时必须处理已停用/已销毁情形，避免残留订阅。关闭先清所有权再执行释放，晚到回调通过活动/销毁状态守卫拒绝投影。

仓储释放最后一个 UI 消费者时沿用索引原有取消机制，不另建隐藏缓存服务。业务层若有其他合法消费者，可继续其独立工作。物流后台服务、工单、资产声明和已有全局预算不受切页/关窗影响。

统一窗口低频复验世界对象、当前玩家、Ledger.view；失效即关闭并清旧视图，命令仍调用现有权威服务重新验证。关闭帮助、仓储编辑流程和手柄焦点均转交外壳协调；切换页签提供键盘/手柄可达操作，并保留原页列表导航和仓储翻页操作。

## 必要验证与边界

实施时递增到0.16.0并更新版本引用、CN/EN文案及进度。只跑相关页面生命周期回归、当前真实 Kahlua 的 CN/EN UI检查和必要 preflight/release-check，不重复历史玩法全套。

重点验证：初次仅激活目标页；反复切换无重复订阅；隐藏页不投影；物流仍运行；关闭幂等；同步订阅回调期间关闭仍释放；跨世界/离开据点清旧页面；重开/兼容入口复用外壳；搜索与工人选择恢复；定位/帮助/焦点释放。ISUI替身验证与真实游戏渲染明确区分。

实机仅需日常观察一次双页切换、关闭重开与运行中物流，不安排冗长人工清单。真实帧耗时、任意UI缩放和其他模组兼容仍未验证，不承诺性能收益数字。

本轮不修改 Java、库存查询策略、搬运原件协议、任务调度或权限模型。后续 Java 批量库存读取/ID定位继续依据实测单独推进。
