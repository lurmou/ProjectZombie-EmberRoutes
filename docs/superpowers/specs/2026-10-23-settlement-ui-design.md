## 1. 页面职责与总体结构

保留用户方案的四页主控制台，外壳管理身份、导航、焦点和页面生命周期；两类快捷入口共用一个委托/最低存量编辑组件，以来源参数配置展示。不是两套下单业务。

| 页面/入口 | 主要区域 | 业务职责 |
|---|---|---|
| 仓储总览 | 搜索/分类/排序工具栏；物品网格或列表；选中详情 | 查询、收藏、来源定位、物料驱动委托及规则设置 |
| 工单监控 | 状态筛选；活工单列表；选中Order的阶段、数量、BOM和内联物流 | 查看与控制已有Order，不承担全局配方黄页 |
| 人员管理 | 人员列表/选中详情；可切换的全员工作矩阵 | 单人精确配置与全局批量配置同一份人员策略 |
| 防御战备 | 警报与热度；哨位/路线列表；装备策略详情 | 配置据点策略，不直接控制某NPC动作队列 |
| 仓储快捷弹窗 | 物品/必要配方选择；单次委托；最低存量 | 带入物料和据点，不带执行者 |
| 原版制作快捷弹窗 | 已选配方/据点；单次委托；可展开最低存量 | 带入配方参数，不改变玩家即时制作逻辑 |

主窗口960×640只作初始参考；弹窗不固定为240×150或340×300。宽度、行高、最小可用区域按字体与控件测量，使用Layout的相对区域和间距。宽屏列表/详情并列，窄屏改为列表→详情导航，矩阵允许横向滚动并保留姓名列。内容放不下时滚动，不缩小字体硬塞、不产生负尺寸。

顶部只展示已知的据点状态；页签角标来自订阅摘要，不为隐藏页启动完整查询。底栏显示有来源的统计与盘点覆盖；发电机、人数、热度等后端未提供时不拼装假数据，不用零代替未知。原版暗色背景、金/白文字统一经Theme控制，具体颜色与间距后续视觉阶段调整。

## 2. 仓储与库存语义

- 搜索、分类、收藏、排序、网格/列表切换保持选中项和合理滚动位置。高密度图标槽随字体缩放，不能把40×40写成永久约束。
- 收藏项组成排序结果的首段，收藏段内部按当前排序；超过一行自然占多行，不能挤掉或隐藏其余收藏。显示短数量时，详情保留准确数值和单位。收藏保存为玩家偏好，不改变仓库或NPC权限。
- 左键选中并更新详情；再次激活或详情按钮打开委托弹窗。右键菜单提供定位、收藏、委托、最低存量；键盘/手柄可完成相同操作，不能把定位和收藏绑定到同一个无菜单右键动作。
- 仓内实物、已预留、搬运在途是不同维度。预留物品仍在仓内时计入实存，不能将三栏相加或从实存机械减去预留。最低存量继续采用已批准的仓内实物口径；在途标方向及关联Job，不计作已经交付。
- 保留盘点中、未加载、权限不足和观察失效状态。局部盘点不能宣称全据点准确总量；未知不是库存为0，不触发误补货。
- 零库存可制作项来自有界、缓存的配方投影，明确区分“有配方”“当前材料可满足”“有合格工匠”。无工匠可以是合法Order的待领原因，不直接判定下单非法。多个配方时在轻量弹窗选择，不扩成另一配方黄页。
- 液体按容器显示类型、当前量/容量、污染或混合状态，筛选使用独立字段。可展示同口径汇总，但不称作可直接消费的共享储量池；不与实物件数相加。水质不明不能计作已知饮用水。
- 复用WarehouseLocator的来源复验及限时高亮；不是跨地图、未加载箱子的全知定位。拼音检索及液体投影属于待补能力，不能由界面文字冒充已有。

## 3. 共用委托与最低存量编辑器

入口上下文包含settlementId、可选productType或recipeId、sourceContext。切换据点或配方后重新预检；没有据点上下文时先选择有权限的据点，不静默使用上次NPC所在据点。

单次委托使用“目标成品数量”作为主输入，展示产出单位、单次配方产量、预计制作次数与预计实际产量。例如每次产3件、目标5件，显示预计2次/6件；不要把成品5件显示成配方执行5次。产量动态或未知时显示明确限制，不算出伪精确值。“最大”只在有可验证、有限且含声明约束的上界时提供，否则移除。回车提交仅在数量输入有效且焦点/弹层允许时生效，提交中禁止重复点击；失败保留草稿。

最低存量在两种入口中均可展开：启用、触发阈值、单次发派量、单位、当前规则/活动Order，提供保存和移除。阈值与发派量不是同一字段。发派量应显式标注成品数量或配方次数，展示对应换算，往返编辑不得改变其含义。

**业务接入门禁：** 发派量单位的持久化格式、配方变化迁移、固定批次是否提前收束，必须在最低存量业务修订中锁定并验证后绑定UI；本文不静默改变旧规则。现有StockStore格式1仍含npcId，StockRule仍按缺口计算，不接受用旧minimum字段冒充新发派量。两个入口最终调用同一规则命令，同一规则只存一份。

公共Order命令不得带执行者npcId，不直接调用Production.execute。预检是只读建议，提交后由本地权威重验身份、权限、配方、数量和目标；工匠技能、配方掌握和领单状态在认领时再验。未知条件、无平台或平台未加载分别说明，不把无平台配方强制绑定家具。

## 4. 工单监控、暂停和取消

列表主身份为稳定Order ID，显示目标、状态、已交付/目标数量、认领者或待认领原因；详情再展开Job、BOM及相关物流。已制作与已入库分开，不把处理中产物算交付。每件工序的计划依赖与实际执行事实分开；当前ProductionChainPlan可复用，但不能由树图假定多NPC已经协作。

显示状态使用业务投影，至少区分待认领、执行中（含离散阶段）、条件等待、暂停请求/停止中、已暂停、取消收尾中、待归还、需核对、已完成和已取消。UI不按本地计时自行从“停止中”改成“已暂停”。

| 操作 | 意图 | 终态条件 |
|---|---|---|
| 暂停 | 禁止新认领/续执行，活动Job请求安全停止 | 身体已确认停止，效果及原件义务已记录；原件仍可留在原Job |
| 继续 | 对原Order/Job提交恢复候选 | 重验原件和条件后由统一执行权仲裁，不新建重复生产任务 |
| 取消 | 关闭后续分配，活动Job停止并完成交付/归还或明确交接 | 已发生效果已归账，尚存义务得到处理；不是点击后马上删除记录 |

取消文案为“取消并处理剩余物料”，后续显示归还中/等待容器可用/需核对等真实原因，不承诺退回原箱。已制成产物只交付或按明确业务处置；提交未知时禁止重新制作。TaskController只负责会话交接，资产收尾仍由业务执行器负责。

总体数量进度与当前动作进度分开。原生制作动作时间单位、暂停与倍率适配经验证后才展示当前动作剩余时间；不是整条BOM的ETA。寻路、取货、备料只显示阶段。停止、动作切换、世界或来源失效时撤下旧倒计时。视图不持有TimedAction userdata。

取消独立物流调度页前，先将未完搬运的状态、原件、暂停/恢复/归还入口纳入工单或相关物料详情。独立分拣任务也要有可追踪条目，不能因其不属于制作BOM便隐藏。清扫、守卫等未实现工种不展示能点击的“派发”按钮。

## 5. 人员与防御

人员列表显示头像、姓名、性别、职业、即时动作、健康和可观察危急警报；感染徽章必须有可观察的确诊依据。详情包括原版技能、工种优先级、身心/疲劳/Buff、床位及重新指定、已掌握配方，以及加入/移出随从、避难/战备和驱逐入口。配方掌握可读KnownRecipes；“读过几本书、何时借还”等必须有真实研习记录，不由KnownRecipes反推。随身装备和武器缩略栏留给战术UI。

全员矩阵是人员页内独立视图，与详情编辑同一份策略。0禁用，1最高，4最低；技能等级用独立小标/提示，避免1(L3)混淆。左右键递增/递减并提供等价键盘与手柄操作；列批量调整前明确目标值和范围，提交按修订号重验，并返回逐人拒绝原因。普通优先级只在安全决策点影响工作，不能禁用生存自理、急救或由UI直接打断动作。“全员搬运/战备”不是自动永久覆写矩阵；没有已定义的临时策略及恢复机制前不实现该快捷按钮。

防御顶部使用0级日常、1级防暴、2级戒严，并以颜色和文字共同表达；热度显示数值/趋势、来源有效性及警戒线。哨位支持世界点选单格，巡逻支持连续选择2～3格、预览、确认和撤销，不填坐标。列表显示当前值守者、唯一替班预约、疲劳、缺岗/到岗状态；预约不等于责任已交接，不把示例60%写成已批准阈值。

装备策略按类型、弹药基准和防具要求配置，展示军械库存与就绪度；改策略不等于NPC已完成穿戴。警报触发调度意图，紧迫安全任务按既有仲裁处理，不提供绕过停止核验的“立即清队列”实现。相关后端尚未具备，页面按阶段接入，不制作假读数或自动换岗演示冒充功能。

## 6. 工程和接口边界

复用Layout、Text、Theme、State、CachedList、PageLifecycle、TooltipAnchor及WarehouseIndex/Query/Locator；业务视图经服务生成标量副本，绘制只读缓存。新增组件仅在实际需要时提取，两个快捷入口优先复用同一编辑器，不新造通用UI框架。

目标接口按业务职责定义，不声称已有函数：读取仓储/Order/人员/防御快照，订阅返回unsubscribe；创建Order、编辑Stock规则、请求Order操作、更新人员策略和防御策略。命令包含稳定目标ID、expectedRevision及去重请求ID，结果明确接受/冲突/拒绝原因；UI不传闭包、角色句柄或Session令牌。具体函数名在对应业务实施计划中与Provider/账本一起落定，不另建UI资产账本或调度器。

关闭/隐藏释放视图自己的订阅、盘点请求、定位、Tooltip和输入捕获；业务后台继续运行。新打开视图使用新代次，旧回调不能更新它。ESC/返回依次处理下拉菜单、最上层弹窗和主窗口；世界切换/权限丢失则关闭全部相关层并清理。编辑草稿未保存时先提示丢弃，不能后台静默提交。所有操作提供可见焦点及鼠标/键盘/手柄等价入口。

不做每帧库存扫描、配方全目录规划、技能/生命轮询；需要观察的实时动作由适配器有界更新，事件与分散低频核验结合。关闭视图不产生该视图投影工作，不承诺后台零成本、零掉帧或GPU局部重绘。字号/宽度变化才重排；物品/工单列表仅绘制可见条目。
