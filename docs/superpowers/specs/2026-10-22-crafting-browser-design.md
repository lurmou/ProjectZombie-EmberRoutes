# 制作浏览与条件适配：设计提案

日期：2026-10-22。状态：用户已批准，0.21.0已实施，见[实际范围与验证](../../reviews/2026-10-22/probe-0.21.0-crafting-browser.md)。以下为设计依据，不能替代实际实现和验收。本轮用户要求高思考，重点为按真实配方条件呈现操作、美观、可用和减少文字堆叠。主代理独立完成，不派生代理。

## 依据与选择

已读取[唯一在线需求](https://docs.google.com/document/d/1aTOBrzZvh_iCDkv045HNAV13i7vNf7OHk6E_sE7TWNM/edit)，正文SHA256仍为3A179F1907B8971E0DD13F8FC2FFA300F0661E6F68C7AA0E7EC3E37202499834。遵循第5节配方/技能/工具/原版动作边界和第11节相对布局、组件复用、事件更新。用户已明确手持制作不要求平台，在线旧段落笼统要求工作台不能覆盖这一决定。

参考[AE2官方终端说明](https://github.com/AppliedEnergistics/Applied-Energistics-2/blob/main/guidebook/items-blocks-machines/terminals.md)的搜索、筛选、数量请求与独立制作状态入口；[AE2原始确认菜单](https://github.com/AppliedEnergistics/Applied-Energistics-2/blob/main/src/main/java/appeng/menu/me/crafting/CraftConfirmMenu.java)将计划计算与提交分开；[Factorio开发日志338](https://www.factorio.com/blog/post/fff-338)展示分类制作界面、搜索以及分离不同任务的页签。这些为交互参考，不移植其网络、CPU或游戏业务机制。

考虑三个方向：

| 方案 | 取舍 |
| --- | --- |
| 配方浏览＋动态下单面板＋独立工单视图（推荐） | 适合大量配方，当前条件集中可见，保留搜索与选中；需重组现有页面 |
| 完全沿用PZ原版制作窗口 | 熟悉且可参考原版条件展示，但玩家背包制作与NPC分类仓储委托不是相同流程 |
| 固定多步弹窗向导 | 初次引导清楚，连续下单点击多，修改数量/配方容易丢上下文 |

选择推荐方案。原版负责配方、动作和物品状态的真值；EmberRoutes负责据点、NPC、供料和工单交互。复用PZ的字体、图标和原生控件，不要求复制原版窗口布局。

## 页面与主要操作

保留顶层仓储／物流／制作。制作内部提供“配方”和“工单”两个视图，返回配方时恢复搜索、分类、选中、滚动和下单草稿。工单视图计数不冒充支持多人排队；首轮仍尊重每个NPC只能保留一个生产父单。

配方视图：左侧为搜索、分类筛选及有名称的物品卡片网格；右侧为选中配方、原料工具、条件与下单。分类随宽度折行或收起，卡片列数随容器和字体计算。窄窗口改为列表与可返回详情，不强塞三列。

右侧顶部固定产物图标、名称及每批产量，底部固定目标件数、执行人和主操作。中段仅滚动材料/条件；阻断原因应在主操作附近可见。不存在适用内容的区域不占空行。草稿和已接工单各自独立，不再用一张卡切换解释两种对象。

## 制作方式与设施显示

| 真实条件 | 默认显示 | 按需操作 |
| --- | --- | --- |
| 手持、无需表面 | 标题边的小“手持”标记 | 完全移除平台选择、设置按钮和平台错误；不保留灰色控件或空白占位 |
| 通用表面、已有可用登记平台 | 一行“平台 ✓ 平台名称”，位置悬停/展开可见 | 默认复用仍有效的原选择；未指定时可自动选合适登记候选，提供“更换” |
| 通用表面、没有可用登记候选 | “尚未登记可用平台”提示卡 | “选择平台”引导现有世界右键登记流程并保留草稿；此时才展开所需操作 |
| 指定平台正被占用/未加载/不可达 | 保留该平台名称与具体原因 | 显式换平台；不偷偷替换执行中工单的原平台 |
| 专用设备且执行适配已实现 | 对应设备名称、状态及必要条件 | 仅列满足该配方实际条件的候选，不混入普通桌子 |
| 专用设备、液体、燃料等机制尚未支持 | 可查看配方信息，明确“暂不支持此制作方式” | 不显示可执行下单按钮；不能伪装成补个工具/设备就能启动 |

当前只有手持与通用表面的受限固定物品执行路径；专用设备一行是未来共用显示契约，不代表本轮实现锻造、烹饪等原生动作。配方同时声明多种标签时先查原版语义，不自行解释成任选或全部必需。

自动选择仅从已登记、可证明有效的当前据点候选中进行；注册记录为空不等于世界里没有桌子。当前仍是显式右键登记，不因为一个“自动”文案假装已有全家具扫描。原选择失效要显示原因；执行中的原平台身份保护继续有效。

## 原料、工具、产物

原料与工具用原版物品图标槽、名称和数字区分，增加短标签和形状状态，不只依赖颜色。工具用保留/归还标记，不与消耗材料混算。没有工具要求就省略整组。

每批配方用“原料槽 → 产物槽”表达关系；目标数量变化时默认显示整单消耗总量，旁边可展开每批明细。工具按同一批次实际同时需要的数量保留，不能随批次数线性增加。副产物单列并包含在交付预览，不把副产物数混进主要目标件数。

替代材料归在同一输入槽内，使用“任选一种”标记，点击可展开全部允许替代项；不自动轮播。不同输入槽分别列出；同一个物品不能在几个有重叠替代集合的槽里重复算成已满足。首次有界查询完成前显示“核对中”，不把未知显示为0或足够。

数量示例：选中锯原木后，目标为“获得1块木板”；摘要为“制作1批，实际3块木板（多2块）”，原料为1根原木、保留1把可用锯。目标改4时，摘要为2批/6块木板/多2块，原料2根原木，锯仍1把。保持目标产物件数语义，不暗改为制作次数，也不默认以仓库现存量抵扣本次请求。

仓储可用数量只来自符合权限、分类、用途和认领约束的实际候选；玩家背包、私人、未登记容器不计入。汇总/未加载部分不能保证可取，需显示覆盖或未知状态；“找到一把锯”也不保证其耐久、原版状态或认领满足，预检需区分。

## 条件和状态是可操作的

兼容性与当前条件分别判断。已适配配方可能缺材料，材料齐全的配方也可能没有执行适配。

| 当前情况 | 表达与操作 |
| --- | --- |
| 条件齐全 | 勾形标记；显示“下单制作” |
| 缺料 | 原料槽缺口数字和警示标记，点击跳转仓储筛选/来源；主操作附近标明缺什么 |
| 可以建单但缺料 | 允许明确选择“建立待补料工单”，说明补齐后手动继续；不暗示后台会自动补货或自动唤醒 |
| NPC不会、技能已够且玩家会 | 知识条件旁显示“传授”；完成后再按实际结果刷新可下单状态 |
| NPC技能不足 | 展示技能图标和“当前/要求”，换人可解决时提供执行人入口 |
| 工具被占用/失效 | 工具槽显示占用或不可用原因，不能笼统说库存为0 |
| 资料或区域尚未核对 | 中性“核对中/部分区域未加载”，不提前绿色通过 |
| 执行后条件变化 | 工单页显示停在哪一步、具体原因和下一操作；保留已完成制作/交付数量 |

知识、技能、设施、材料、兼容性存在多个问题时都可展开查看，不用一个首错永久遮住其他问题。主操作聚焦当前最直接的下一步，不出现一整排互相重叠的按钮。

库存预览只是本次条件快照，不锁定资产；下单及原生效果前保留现有权威复验。目的地容量/通路等尚未完成核查时明确“执行前复验”，不以静态数量伪造一定可完成。

## 工单视图与视觉规则

工单按产物、主要状态、真实产出/交付数量和执行人展示；展开后才显示细节。选中工单不改变配方草稿；正在制作时仍能浏览其他配方。没有可接单NPC时明确显示原因，不偷偷改成新执行调度机制。

配方浏览用图标/名称/状态角标；条件用图标槽和缺口数字；工单用原有阶段轨道、暂停/完成形状与数量条。正常状态压缩呈现，异常就地展开；详细解释放在点击展开或Tooltip中，但关键阻断信息不能仅靠悬停。

延续PZ暗色半透明面板、金色选中/主要操作、柔和中性色和原版图标。单一主要强调色；红色只用于明确问题。保持文字对比、键盘/手柄焦点与大字体可用，拒绝为了小图标压缩点击区域。切配方时只重排详情内容，不改变整个窗口尺寸；滚动位置、已输入数量和焦点按稳定ID保留。

## 数据与性能边界

展示描述、条件预检、下单命令、工单状态四层分开。描述来自当前加载的原版/模组配方，记录稳定recipeId、制作方式、输入槽、保留工具、主要/次要产物、技能及知识条件和机制支持状态。未知机制可查看，不自动承诺执行兼容。

浏览基于缓存、分页和可见卡片复用；目录首次加载分片有界，加载未完成要有状态。搜索基于缓存的当前语言名称和分类，不每次重新扫描库存、家具或全部脚本。不以完成目录枚举等于完成原版动作适配。

只对当前选中配方、数量和执行人运行有界只读预检。预检复用当前供料候选/分类/权限/认领规则；记录世界、据点、recipeId、签名、NPC、数量和查询代次。切换时取消旧请求，晚到结果不得覆盖新选择。预检不领取资产，不启动移动、不修改原单。

仓储和认领变更只使相关结果失效，合并更新；供料匹配保留替代项去重、全局预算和容量限制。关闭/隐藏视图释放订阅、弹层、Tooltip和查询，后台已接工单按现有生命周期继续。库存变化不使整个配方网格反复重排。

## 本轮完整切片与验收重点

建议下一轮实施：配方搜索/分类浏览、按配方条件动态下单面板、选中配方预检、独立工单视图以及与原仓储定位交互。最低存量、递归BOM和新制作机制随后接同一入口，未实现前不展示假开关/假按钮。

必要验证关注手持无设施控件、平台缺失/失效/占用、无工具、多替代材料、目标与整批产量、旧查询晚到、隐藏释放、CN/EN和大小字体。用已知不同结构样本验证显示契约；有限宿主/静态检查与实机结论分别记录，不重跑无关历史全套。
