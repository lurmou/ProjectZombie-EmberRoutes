# 末世据点行动档案：整体导航、工作分层与 UI 基础设计草案

> 状态：v0.2 设计草案。用户反馈整体 UI 混乱，要求对照 ProjectRemnants 重新设计；尚未实施或验收。运行基线 d7fbbce / 0.29.38。

## 目标与边界

需求页帮助玩家判断“哪里有问题、影响谁、谁在处理、卡在哪里”；工单页帮助玩家判断“安排了什么、谁在做、已有多少真实成果、是否需要干预”。自动清洁只在需求页，同一问题汇总一条；原件归还显示在原工作内，不增加独立工具托管工单。

本轮设计不更改工作调度、医疗/清洁效果、搬运路线或存档。在线唯一需求第 11 节已读取：经典暗色、暖白/琥珀金、组件复用、相对布局、单向快照仍作为底线。用户本轮明确要求更激进的视觉及重看整体 UI；本稿提出导航重组供审阅，不修改在线需求、不新增经营功能。

## 布局方案与取舍

1. **推荐：四个主入口 + 最多一级页内导航。** 据点、仓储、人员、工作。需求/工单依然分开，归入工作；已有活动/防务归入据点。每个动作有一个主要归属，其他页面以带上下文的跳转到达。代价为导航重组及选择/返回路径适配，需要用户确认后实施。
2. **保留七页，只统一样式与快捷跳转。** 实施影响较小，但工作相关入口继续散布，仅靠文字解释难以消除混乱。
3. **照搬参考的三个主入口。** 表面更简洁，但把本项目需求/委托/执行责任全塞进“成员”或“据点”会再次拥挤，不采用。

| 主入口 | 玩家目的 | 页内内容与边界 |
|---|---|---|
| 据点 | 管地方 | 当前据点状态、范围/设施/区域；活动与防务作为已有次级内容。只汇总已有事实，不编造评分或新增一套任务列表。异常计数跳到工作中的对应需求。 |
| 仓储 | 管物资 | 聚合库存、来源与容器规则、待送清单。选中物品后发起制作/配送，提交后可跳到工作中的对应安排；不复制工单监控。 |
| 人员 | 管人 | 名册、健康、岗位及工作偏好；0～4 优先级是同页“分工”视图。点击成员看详情，技能/知识沿现有档案。长期工作偏好只在这里编辑。 |
| 工作 | 管事情 | 需求 / 工单 / 规程三个页内视图。需求看问题，工单看具体安排及成果，规程设据点范围规则。工种是这里的分类和上下文，不各开一个主页面。 |

首开工作默认进入需求，之后记住玩家上次页内位置；异常不强制切页。顶部只显示当前据点、主要导航与必要异常提示，不常驻一排零计数状态。主导航不再与全量状态筛选、创建按钮挤在同一行。

整体目标与实施切片区分：先通过现有 PageRegistry/窗口把现有页面挂到明确的分组入口，再重新构图工作中的需求/工单；人员名册/分工布局随后独立细化。不是本次设计就重写所有业务页。参考有而本项目尚无的农田生产、单工种指派等功能不提前画成可用按钮。

### 对象与操作归属

- 看“谁在做”去工作；改某人的长期偏好去人员；改伐木区域/农田等空间设置去据点；改补货和工具等据点规程去工作/规程。每种设置只有一个编辑权威。
- 从工作点击某人，到人员中定位同一 stable npcId；从需求查看处理安排，到工单定位有关联的安排；从工单查看材料，到仓储定位物品。带上下文跳转，不要求玩家重新搜索。
- 工作详情里的工具、材料、参与者和阻碍属于选中工作的展开内容，不再各开顶层栏目或窗口。没有异常时不显示占位“处理原因：正常”。
- 清洁等持续维护仍在需求中汇总处理者/当前动作，不重新生成一份同名工单列表条目；缺木材这类问题可链接伐木生产安排，问题与安排使用不同标题和含义。不能仅按产品名把不相关工单合并。

### 砍树、农务与多人

职业是成员属性，页面展示实际事情：伐木看区域、执行者及已确认产出/交付；农务看浇水/收获/清理及区域；制作/烹饪看产品与真实成果；搬运看物资、去向和逐件交付。当前农务只核实到 WATER/HARVEST/CLEAR，不能把参考项目的开垦播种画成我们的已支持功能。

一个概览行可以展示多个真实 Job 的处理者头像/姓名与“几人处理中”，展开才看每个人的不同目标；底层 Job 仍各自一个 npcId，目标/工具声明不共享给两个执行者。没有稳定业务关联时只按工种分类展示，不捏造多人共同工单或共同完成百分比。

**手动指派仍是待单独确认的业务功能**：现有工单命令仅 stop/resume/return，优先级/岗位设置不等于把任意正在执行的 Job 转给他人。UI 重组可先呈现实际执行者和分工跳转；正式增加“自动/指定人员、候选多人、并行人数”前，另设计权限、候选条件、交接、原件留责与恢复，不用 UI 直接改 npcId，也不放一个看似可用的虚假选人按钮。

此前“行动档案/现场简报”草图仅是需求/工单的局部构图比较。用户已选过现场简报作为偏好；本次整体结构修订后，旧草图不再充当整体导航或手动/多人功能的确认。先确认信息结构，再按同一壳体重画完整操作路径。草图不是游戏实现，不打包进模组。

### 需求页：现场简报

- 顶部为少量需求入口，显示问题名称、数量及简短状态；较多需求可沿现有有界列表导航，不能无限横向堆卡片。
- 主区以问题标题与“54 处待清理”这样的真实量为视觉中心，影响范围紧随其后。
- 当前处理者用缓存头像、姓名和一个当前动作表达；无人处理显示待分配，不放空白人物卡占位。
- 阻碍独立显示，仅受阻时出现；“已安排”不与过期的“等待人员”并列。未知结果必须显著保留。
- 工具/材料以紧凑物资格子展示；坐标、观察覆盖及托管责任在展开详情内。清洁没有可靠总量时只显示待处理数，不画虚构完成百分比。

### 工单页：行动档案

- 索引默认约占宽度 24%，同时受最小/最大宽度约束；条目只保留名称、执行人和一个真实状态，不重复摘要、阶段和处理原因。
- 主区标题、成果大数字、细数量条形成第一层；人物与当前动作第二层；原件状态物资第三层。
- 生产可分别显示已产出/已入库，搬运显示已交付/总数。不能把“已取出”“已入队”当完成。
- 步骤仅以业务已确认事实展示；默认不展开逐件技术轨迹。坐标、尝试和恢复说明放在详情。
- 正常时只有一个主要操作，次要与破坏性操作收低；允许/禁用及原因沿现有 Service 命令契约决定。

## 基础设施增量清单

| 能力 | 决定 | 具体范围与消费者 |
|---|---|---|
| 状态、列表、生命周期、提示 | **直接复用** | State、CachedList、PageLifecycle、Tooltip；两页不增加第二个 Store、Watch 或事件总线。 |
| 数量条、筛选、物品纹理 | **直接复用** | StatMeter、FilterChips、ItemPresentation。真实数量由 Service/Presentation 提供。 |
| 字体、间距和表面规范 | **扩展 Theme** | 新增 title/metric/body/caption 角色、统一间距尺度及 plain/inset/briefing 表面规格。最终字体映射 UIFont 与实际字号测量；草图 CSS 数值不能承诺游戏逐像素一致。颜色仍从登记的主题/状态取得。 |
| 窄索引与主区布局 | **扩展 Layout** | 在既有 axis 旁补有界 split 计算：索引最小/最大宽度、详情最小宽度及 compact 模式。订单/人员现有双栏均为真实参考；首批只接需求/工单，不顺带重做人员页。未使用新约束的 axis 调用行为不变。 |
| 主导航与页内导航 | **扩展 PageRegistry/SettlementDashboard** | 现有 parentTab 仅能关联主按钮高亮，不等于完整分组导航。补明确分组/默认页/返回与定位上下文；每次只激活一个业务叶页面，继续沿原 selectTab 的 deactivate/activate。无需新路由引擎、页面工厂或第二套生命周期。 |
| 去盒子感、轻状态 | **扩展现有 CardPanel/SemanticBadge** | 增加无外框/细分隔线表面、轻徽标，字号/文字宽高在 prepare 缓存。InfoList 消费这些描述，不做第二套状态配色。 |
| 大号摘要与分区详情 | **页面组合** | 摘要不再被强制做成“长列表的第一行”；两页分别构图，继续复用 InfoList 的次级可滚动细节。不把需求页绑定到工单页的整页构造函数。共享激活/订阅机制仍沿 PageLifecycle，不新建通用页面工厂。 |
| 物资格子展示原语 | **首批新增 1 个公共 Widget：ItemSlot** | 只接收 icon/name/countText/status/selected，缓存排版与命中矩形，绘制阶段只读。需求工具、工单原件先用；仓储/配方既有展示作为契约参考，后续迁入时保留各自选择/计数语义。格子不直接查容器或生成物品。 |
| 人物头像展示 | **修复并扩展既有 Avatar3DView 与 PersonnelService** | 通过稳定 npcId 获取选择中人物的有界缓存快照；Java 取图在激活/失效后的更新路径执行。setPortrait 接受纹理与回退信息；prerender 只画缓存。不另做每帧 3D 人物窗口或全员头像轮询。 |
| 折叠、抽屉、时间轴、动画 | **首批不新增框架** | 折叠沿已有 expanded 状态。新图表、通用 Drawer/Timeline、动效引擎没有本次必要性；队伍/路线动画也缺少足够业务事实。 |

选择以上增量而非只换皮，是因为现有整页继承和单列表详情妨碍不同构图；选择扩展现有组件而非重建框架，是因为状态、列表、文字测量、滚动和资源所有权已经存在。收益目标为减少重复信息、改善识别与排版；没有测量前不宣称帧率提升。

### 新能力的契约边界

- ItemSlot：`prepare(spec,bounds,themeRevision)` 生成缓存；`draw(owner,cache)` 只读；`hit(cache,x,y)` 与绘制共用同一命中范围。数量、托管含义、点击动作由业务层决定，Widget 不识别 Job 或 InventoryItem。
- Theme：主题变化需要使本页缓存失效，按 activation scope 登记/释放主题通知；不在每帧发现失效后做投影。旧默认表面与字体不因新增样式全站替换。
- Avatar：服务控制观察与纹理缓存，组件只持有当前快照。装备/衣物变化沿现有失效事件，缺少事件的失败重试仅在激活且可见的选中人物上有节拍推进。共享引擎纹理不由页面销毁；页面退出清引用、释放监听与重试任务。无法取得头像时用职业图标/姓名回退。

## 生命周期闭环与事实来源

创建：`UI/PageLifecycle.lua:160` 创建 activation token，`:194` own 与 `:258` watch 接管新资源。正常切出/关闭沿 `:420` unmount → `:303` dispose 解除订阅、主题通知、头像失效监听与刷新任务。异常/迟到回调沿 `:182` wrapCallback / isCurrent 拒绝旧 token；释放中的单项异常由现有隔离机制处理，不影响其他页面。

DemandMonitorService.status/watch 与 OrderMonitorService.status/watch 保持只读事实入口，工单指令仍走 Service。原件归还/UNKNOWN 由原业务处理，隐藏一条 UI 不代表责任结清。页面不读取 ModData 根表、不查询身体或容器，也不新增医疗/搬运的持久字段。

## 验收与当前证据

- 清洁进行中、无人、缺物资、UNKNOWN；生产未开工、部分成果、用户暂停；携货与部分交付均有清晰而不矛盾的显示。普通工具留在原工作内。
- CN/EN 长名、数量变化、字体放大、窄窗口、窗口重开/切页，选择与滚动锚点保持；绘制与命中同源。
- render/prerender 的文字测量、实体查询及动态表分配禁止进入新分支；头像取图离开绘制阶段。暂停/取消命令的守卫与参数不随视觉变化放宽。
- 新 Widget/布局的有限断点、缓存与生命周期做定向宿主检查；最后一次实际组件预览及实机对比。浏览器草图不替代 PZ 字体、纹理裁剪或游戏性能验收。

v0.1 交互草图的片段结构及 JavaScript 语法检查通过；两个浏览器入口初始化失败，未做渲染/交互验收。v0.2 只读核对参考 Lua 与当前根 JAR 的工作分配桥、核对本项目导航/页面职责并修订信息结构，没有修改运行 Lua/Java，没有运行模组业务测试或构建。下一步为用户审阅四入口与操作归属，再制作完整流程草图；不是立即实施手动指派、多人协作或所有页面重建。
