# 据点 UI 收敛与交互优化设计

日期：2026-11-05。状态：布局候选 0.29.39 已实施，尚未实机验收；不代表全部设计收口，实际差额见[实施记录](../../reviews/2026-11-05/ui-layout.md)。

依据：用户本轮明确决定和三张游戏截图、当前工作区源码、项目 UI 生命周期规则。在线唯一需求在本聊天已读取；本文是从属实施设计，不建立平行需求。用户已授权自主完成设计，不逐项请求确认。当前工作树有未提交 UI 改动，实施不得覆盖或回滚这些改动。

## 1. 决定与比较

采用保留业务与组件、重整导航和任务流程的方案。只改颜色不能解决重复入口和状态失联；整套重写会扩大引擎生命周期、原件责任和业务回归风险。比较限于当前单人管理 UI，不宣称性能最优。

本轮明确保留 AE2 式制作：产品检索、配方选择、材料树、工具及平台条件、数量、下单。删除独立工作顶栏，以及旧配方/工单顶层导航；制作工作状态转人员管理。制作配方是制作流程的一步，不作为独立管理页复活。需求页、全局工单页不恢复。

最低存量不在用户批准删除范围，保留业务与编辑能力，收在仓储的“库存规则”次级入口；不挤占主制作流程。已有公共下单与指定人员制作的提交契约分别保留，不在 UI 收敛中强行统一业务。

## 3. 信息结构与归属

```text
据点管理 · 据点名称                         提醒摘要
[ 据点 ]             [ 仓储 ]              [ 人员管理 ]

据点：已有生活活动 / 作业与方针 / 防御
仓储：库存终端 → 制作流程；次级入口：库存规则
人员管理：人员与优先级 / 物流
```

子导航只在存在多个同级目的地时显示；单一页面不再重复铺一条全宽同名按钮。顶栏、提醒、页面工具栏采用统一高度与间距，不保留无内容占位行。

归属原则：工作从现有业务入口发起；已分配执行归人员；无人执行与排队事项归对应作业分类；问题提醒只汇总与定位；责任详情归稳定事项 ID。提醒数字之间可重叠，不相加成虚假总量。

“活动”口语不直接等于 ActivityPage：当前社区活动页面有独立用途。普通工作队列继续复用 WorkPolicyPage/WorkQueue 的分类，不向生活活动页混入伐木等业务。

## 4. 仓储与制作流程

### 4.1 仓储终端

首行搜索与清除、分类和库存/制作切换；排序与网格/列表等低频配置进入紧凑视图菜单。主体优先给库存网格，未选择时不留空详情栏；有选中时展示紧凑物品摘要和配送操作，来源按需展开。配送清单与选中详情共用上下文区域，不叠加两套固定面板。区域展开不得使鼠标下物品突然换位，窄窗口用覆盖式抽屉并保留滚动锚点。

“库存/制作”是工具栏唯一常驻制作入口：未选物品可浏览可制作产品；选中可制作物品时切入对应产出。选中不可制作物品时明确显示没有对应配方，并提供清除产品过滤继续浏览的路径，不自动选无关配方。物品详情不再重复放“制作此物品”按钮。

单击选择；双击沿当前确认行为加入配送清单；中键仅作为制作快捷入口，不作为唯一入口。最终按键定义由动作表关联 handler、适用条件和翻译键，Tooltip 与帮助消费同一来源。额外鼠标开关不作为收到中键的证据，实际分发按当前安装 JAR 与原版 Lua 核对。

### 4.2 制作流程

```text
[← 仓储]  制作                        产品搜索 / 分类
┌ 产品与配方列表 ─────────┬ 制作预览 ──────────────┐
│ 产品图标、名称、产出量  │ 产物名称 / 每批产出    │
│ 多配方时明确选择        │ 材料树与缺口          │
│ 紧凑列表或网格          │ 工具 / 平台条件       │
│ 分页只在需要时出现      │ 数量与执行方式        │
└────────────────────────┴───────────────────────┘
                           阻碍摘要   [提交制作]
```

不再出现“制作→配方”重复标题、orders 页签或工人列表。布局先保证右侧材料和提交区可读；宽度不足时，左侧缩为产品选择列表，选定后以详情视图展开，提供明确返回，不挤成不可点击的小列。

数量使用 StepperInput；预览显式区分批数与目标产出，避免输入 6 被理解为 6 批或 6 件。延用现有业务单位，不在本次视觉修改中改变计算语义。最大数量仅在已有准确可计算能力时出现。

必要条件、阻碍及提交按钮相邻；按钮禁用时提供具体原因。提交中阻止重复发送；成功显示业务返回的真实结果，并提供“查看工作”定位人员或未认领制作分类。失败保留输入，不自动清空。提交成功不强制跳走；返回仓储恢复视图。

### 4.3 返回状态与生命周期

返回上下文保存据点 ID、搜索、筛选、排序、视图模式、选中 fullType 和滚动锚点等纯 UI 值；不保存实体引用，不扩展为通用历史栈。返回时重新取有效数据：物品消失就清选中并提示，不能恢复陈旧实体。

展示状态由 Dashboard 在当前窗口内持有；关闭窗口释放，不持久化到业务账本。页面 deactivate 仍撤销 watch/异步/Tooltip，不能为了保留筛选而留住资源。页脚跟随实际流程，不再继承人员优先级说明。

## 5. 人员管理与工作详情

人员页保留矩阵为主、详情为辅。宽度由字体、实际工种列数及最小姓名宽度计算，不固定 65/35。矩阵不足宽时只在工种区域水平滚动，姓名列固定；表头与行共享列布局及滚动偏移，禁止独立计算。

每行姓名下显示同源当前工作摘要：动作/对象 + 状态；不在顶部再复制一份全员名单。全部、工作中、空闲、受阻筛选复用 FilterChips；等待、暂停不冒充空闲。

默认矩阵占主区域，未选人时不留空右栏。选中后详情区域按空间展开，顺序为阻碍/进度 → 可用操作 → 保留责任 → 完整档案入口；姓名只作为定位标题，不再重复一整张肖像、据点、位置和工作卡。健康、精力等完整身体数据归档案；急需关注的伤情保留在行内警示与提醒。详情展开不得重新分配优先级单元格的命中位置；窄窗口用抽屉覆盖，不压缩矩阵为难以点击的小格。

必须区分“当前身体动作”和“保留工作/原件责任”。同一人有多项责任时展示折叠分组；不能任取第一条保留 Job 宣称当前在做。服务缺乏明确身体事实时显示“当前动作未确认”，列出已知工作，不解析活动文本猜测。

暂停、恢复、取消及归还仅由 WorkCommandAdapter 的真实能力决定。FIELD_WORK 现有 stopBody 明示“停止当前动作”，说明后续仍可能按方针重新认领，不展示不存在的持续暂停能力。优先级调整旁说明“影响后续派工”，不承诺立即打断。

## 6. 队列、提醒与复杂责任

作业与方针分类中，上方是该类真实待办/执行/受阻事项，下方是对应设置。制作分类承担未认领订单入口，并可查看仍有责任但暂无执行者的事项。已完成且结清事项不占实时队列；取消但未结清责任不能因状态终止而消失。

提醒摘要优先嵌入公共标题区的固定槽位，无异常只保留轻量状态，不额外占一整行；异常出现不能使正文跳位。有限宽度收为“提醒 N 类”入口，展开只列提醒种类与数量，不复制全局详情列表。面板外 HUD 不在本轮范围。

数据不可用显示不可用；食物/水缺乏类型化问题源时不显示伪造计数。点击提醒先定位真实对象，失效则显示“事项已变化”并刷新，不默认跳到无关人员。

复用监视详情卡构成“工作详情”抽屉，显示当前阶段、已产出、已交付、原件/工具责任、阻碍和实际支持的命令。人员行、分类事项均可打开；它是单事项详情，不是新的全局工单页面。

身份继续沿现有领域前缀 id、npcId、orderId、generation/revision；不同域不强行统一代次。UI 只存定位键，打开和提交命令时重新解析；对象缺失不能作为原件已结清证据。

## 7. 公共组件、视觉与翻译约束

| 内容 | 复用入口 |
|---|---|
| 页面尺寸、间距、文字截断 | Layout / Text / UICache |
| 列表及分类过滤 | CachedList / FilterList / FilterChips |
| 数量输入 | StepperInput |
| 普通信息卡与状态 | CardPanel / SemanticBadge / StatusVisual / StatMeter |
| 剪裁与浮动提示 | Viewport / TooltipManager |
| 激活、订阅、失效门禁 | PageLifecycle |
| 唯一颜色、控件状态 | Theme |

复用前检查组件真实契约，不因文档列出就假定满足；有缺口时按实际两处需求扩展，不建立第二套相同控件。业务网格和矩阵允许专用布局，但不复制通用输入、卡片和提示机制。

风格延续原版暗色、暖白正文和克制琥珀强调。强调色只用于当前选择和主要操作；健康、警告、错误附带文字/图形，不能只靠颜色。静态标题不绘成可点击的大按钮。空状态按无数据、无搜索结果、读取失败、无权限分别解释。

尺寸以 fontHeight 为基准；主要操作高度至少约 1.8 个小字体行高，间距从统一 Theme/Layout 规则取值，最终按游戏字号验证。正文避免过暗和多重半透明叠加；不引入网页字体、装饰动画或未验证材质。

翻译键检查包含静态引用、动态前缀与后缀集合、CN/EN 配对、格式参数数量，以及实际数据投影后的可见文本。原始 IGUI_/UI_ 键不得进入普通玩家文字。开发检查明确报缺键，不能以中文 fallback 让检查假通过。自由输入名称和物品 fullType 的诊断显示不混同为翻译键。

动作与提示共享定义后，检查其关联与适用条件；仍需人工审查文案语义，键存在不代表内容正确。删除旧页时只删确无生产引用的专属键及组件；共享详情卡保留。

## 8. 数据、所有权与语义边界

数据链保持 Service → 纯 Presenter → Store/缓存 → render；UI 命令经现有业务入口，不直写 ModData，不引入第二权威或新结算者。

所有权 Dashboard → Page → 列表/详情抽屉/Tooltip/Watch。打开时认领；正常切出时按 activation token 失效并释放；异常回调、关闭、据点切换后不得写入新页面。浮动详情由打开它的页面拥有，切页关闭；跨页定位用稳定键重新打开。

现有闭环证据见分布式工作实施记录：FieldWork 创建认领、FieldSession 正常收尾与 stopAdapter/persistFailure；本次不更改这些业务职责。UI 的按钮迁移不改变权限、generation 守卫、持久格式、身体停止和原件释放语义。

render/prerender 只读缓存；文字测量、拼接、快照投影在置脏时完成。服务有失效通知则订阅；无事件的真实身体观察沿既有活跃节拍，不新增全员逐帧扫描。性能未测量，不宣称帧率提升。

## 9. 删除范围与实施次序

1. 对照当前未提交改动冻结入口、动作和翻译引用清单，先补必要事实缺口，再做视图迁移。
2. 仓储→制作闭环：将 crafting 注册为仓储流程子页，移除 work 组与重复子导航；保留 CraftingBrowser/Draft 的有效实现并统一数量、布局和返回状态。
3. 人员与事项闭环：迁移 CraftingOrders 中仍有效的只读详情及命令到人员/分类队列/详情抽屉；覆盖无人认领、多保留工作及未结清责任。
4. 库存规则移至仓储次级入口；在调用切换与检查完成后删除旧 CraftingOrders 页面层及废弃导航分支，不留旧 view='orders' 转发兼容。
5. 统一提醒、翻译、空状态和公共视觉；同一批完成遗留入口/专属文案/死代码清理，不以隐藏旧按钮代替删除。

组件与状态迁移是结构重整；三顶栏、制作归仓储、工作归人员/分类是用户批准的导航变化；返回保留状态及更明确反馈是本设计的交互优化。后端持久暂停、食水问题来源、新手动工作目标均不夹带实现。

## 10. 验收与交付

必要定向检查：三顶栏及旧入口零引用；仓储进入/返回保持纯 UI 状态；制作提交成功/拒绝/重复点击；人员表头与行一致；无执行者仍可定位；旧代次命令拒绝；取消未结清责任仍可见；切页后回调无效、watch/Tooltip/抽屉释放；真实 CN/EN 文案键与格式校验。

视觉样本集中覆盖：本轮截图相近窗口宽度、1080p、2K/4K可用字号；CN/EN、长姓名/长产品名、多人员、所有工种、无数据与阻碍状态。具体分辨率与字号以实际运行记录为准，未运行不记通过。合成预览可验证几何，不能代替游戏字体、原生裁剪和鼠标命中。

实机集中验证：滚动边界、表头同步、按钮可见与命中、中键不双触发、弹窗遮挡、制作流程返回、详情命令及关闭后的残留。正式候选集中跑一次所需回归与 preflight，不每个小改动重跑全历史。

设计阶段仅完成源码核对；随后布局实施及已跑检查见上述实施记录。真实游戏、字体布局、鼠标派发、恢复和性能仍未验证。

## 11. 游戏 UI 指南复核与交互补充（2026-11-05）

本节修订前轮“少展示即便捷”的判断。以下是基于指南与截图的启发式评估，不是玩家操作测试结果，也不存在一套适合所有游戏的唯一公认布局。

### 来源与适用边界

- [Game Accessibility Guidelines 基础清单](https://gameaccessibilityguidelines.com/basic/)：工作室、专家与学术界协作指南，覆盖输入替代、易读字号、对比度与非纯颜色提示。用于检查 PC 游戏输入与阅读障碍，不照搬触屏尺寸。
- [Xbox XAG 112 导航](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112)：同类操作位置、导航和输入一致。
- [XAG 113 焦点](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113)：焦点清楚、可见，模态打开期间不进入后方控件。
- [XAG 114 上下文](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/114)：操作前可理解当前位置及操作结果，不无提示改变上下文。
- [XAG 115 错误与破坏性操作](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/115)：错误可解释、可修正，重要变更提供审阅或可逆机会。
- [XAG 101 文字](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)、[102 对比度](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)：按真实游戏阅读条件和背景检查，不按 CSS 字号推断可读。
- [NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)：通用交互依据，非游戏专属标准；高频操作保留在首层，低频功能再展开。
- [Game Accessibility Guidelines 简明语言](https://gameaccessibilityguidelines.com/use-simple-clear-language/)：减少不必要的句长和复杂表述，保留必要含义。

### 逐项结论与约束

| 方面 | 当前/前版问题 | 本轮设计约束 |
|---|---|---|
| 简洁与发现 | 既有多层导航浪费空间，前轮又把所有筛选藏进下拉 | 三顶栏；全部/工作中/空闲/受阻高频筛选直接可见，有宽度不足证据再收纳 |
| 信息密度 | 矩阵、右栏和健康卡重复；一概删除详情又增加寻找成本 | 行内看全员，选中后看阻碍/操作/责任；完整身体属性归档案 |
| 手部移动 | 快捷操作依赖中键；大确认按钮与输入分离 | 鼠标单击可完成主流程；快捷键是补充；数量、缺口和提交相邻 |

### 操作评估方式

集中走五条任务：搜索并加入配送草稿；仓储选产品→调整数量→下单→回到原位置；找到受阻人员→读原因→执行实际支持的命令；无人认领提醒→具体事项；修改多人同一工种优先级。

记录有效点击、跨区鼠标移动、返回重输、误触、找不到入口、失焦及错误理解。正常数据下仓储已选产品进入预览目标为一次显式操作；找到受阻人员不应要求逐个打开档案。点击数只是目标，不能为了少一次点击而增加误触或隐藏后果。

当前没有游戏操作计时或玩家试用证据，以上不得表述成“已验证更人性化”。先以同一组任务对照旧 UI 与候选，再根据实机证据收敛。
