## 1. 文档地位与批准范围

## 2. 术语与不变量

| 对象 | 含义 | 生命周期 |
|---|---|---|
| 需求 Demand | 据点或个人希望满足的目标 | 不直接操作 NPC 或原件 |
| 工单 Order | 对目标数量/条件的生产安排 | 可产生多个执行任务，不能重复结算 |
| 执行任务 Job | 某 NPC 执行的具体工作、自理或跟随流程 | 可运行、暂停、恢复、完成或等待核对 |
| 执行会话 Session | 当前任务获授的身体控制权及代次 | 一次交接一个新会话，不等同于整个工单 |
| 资源声明 Claim | 对原件、槽位或容量的协调声明 | 由现有资源协调扩展，独立于身体会话 |
| 持续义务 Obligation | 炉具监管、待交付/归还等未完成责任 | 不随行为树退出或会话结束而消失 |

核心不变量：每 NPC 同时只有一个主动身体执行者；允许多个暂停任务与持续义务。身体执行权、任务归属和资产托管不能用同一个 busy/retains 标志代替。任务代次、声明代次和会话代次各自有含义，不能用一次吃饭中断作废整个工单。

所有对象使用稳定 ID；原件转移保留真实实例。物理效果由当前单人本地世界执行者裁决，观察、UI 和计划不能直接扣汇总库存。未来宏观结算与实体执行仍须互斥交接。

## 3. 各层职责

### 3.1 宏观 HFSM

仅管理据点生活、队伍跟随、驻守和未来远征/商队等上下文。职业、技能、知识、健康和战备策略分别存储，不组合成状态爆炸。上下文限定允许的行为：跟随时可以在安全间隙自理，不因此自行回据点领生产单。玩家指令和宏观事件驱动上下文切换。

2026-10-25用户选择显式驻扎B并确认由本会话负责实施准备：据点成员资格以稳定npcId关联的持久化factionId/settlementId裁决，不从HOLD或当前矩形推导；归属、宏观命令与实际执行分开。首版context为SETTLEMENT/FOLLOW/WAIT/RETURN；跟随和越界不改籍，几何继续约束实际活动/资源访问。普通工作、研习、闲暇共用按用途资格入口，紧急自理/已有责任不能被成员门禁一概阻断。命令接受即失效旧候选，身体与原件交接仍遵守§4/§5，角色死亡不清成员；无返回目标时明确等待，不默认传送。无旧档兼容，不取消当前格式保存恢复。完整契约、转换及共享接口见[显式据点归属从属设计1.0](2026-10-25-npc-settlement-membership-design.md)，实现与验证边界见[0.27.0开发证据](../../reviews/2026-10-25/npc-settlement-membership.md)；闲暇决策重构由后续独立工作消费该接口。

### 3.2 分级效用仲裁

先过滤权限、上下文、身体能力、知识/技能、资源与可观察条件，再按紧迫等级选择：即时致命危险 → 自卫 → 安全条件下急救 → 紧急个人需求 → 工作 → 闲暇。同级内比较效用。

0～4 工作优先级、技能适配、距离和等待时间用于常规工作选择，不得抵消更高等级生存需求。结合切换滞后、最短有效工作区间、失败冷却和条件变化唤醒；危险可越过普通切换限制。脱离即时威胁后，先由自我照顾模块就地使用可用物资止血保命；出血受控后再评估深层伤情（缝合/取子弹/骨折）流转至公共医护工单；黄色战备不强制中断所有平民生产。无逐小时排班表。底层真实接口对齐规范详见[底层对齐审查](../../reviews/2026-10-23/vanilla-engine-interface-alignment.md)。

2026-10-25用户明确批准驻扎完成后实施P3.5改良：闲暇消费Membership资格，不再依赖PublicWork拥有许可；公共工作只报告有时效的READY/IDLE/OBSERVING。观察未决不认定无工作，但允许无原件、无设施、无社交预约及无移动的短时观察。普通工作收束基于已验证可执行候选，实际启动失败退避；危险和紧急自理仍优先。活动在有界池内比较，慢发现不阻塞已知安全候选。家具姿态仍属于同一Session，退出动画计入停稳；不授权通用姿态任意组合。细化及实施状态见[P3.5设计1.2](2026-10-24-p3.5-leisure-social-fitness-design.md)和BACKLOG。本段记录用户已批准的规则调整，未宣称实机达标。

### 3.3 统一当前任务控制器

2026-10-28用户确认后续生活/活动细化：先建立最小功能子区，区域提供普通行为的禁用/允许/优先；日常公共生活复用现有分级效用选择，聚会按成员/期限提供临时偏好，不强迫全员按同一动作序列。普通聚会采用自由行为集合，演讲/仪式保留共同角色/阶段；不新增第二身体控制、库存或逐小时排班，危险/自理/原件责任仍按既有协议。方向及边界见[活动从属设计0.4](2026-10-28-a3-a4-community-activities-design.md)和[最小公共生活子区](2026-10-28-public-life-zones-design.md)；源码接入和实机状态仅见BACKLOG，不能把此确认当全部功能已完成。

从 Work 抽取通用控制职责，独立于劳动业务；Work 保留劳动服务及迁移兼容入口。Companion、Production、自理、诊断动作和恢复逻辑都申请同一控制协议，不再各自靠互相 cancelAll 协调。

每 NPC 是一个逻辑控制器，不创建独立线程或定时器。控制器管理当前任务 ID、会话代次、交接状态和挂起任务引用；多个 NPC 共享调度预算。

统一出口覆盖移动、停止、动作入队/清队列、自动续工、保存后恢复和读档恢复。必须审查 Java 命令及旧 Actions/Haul 诊断路径的绕行；只保护 UI 或 Lua 高层入口不够。未来一个战斗任务可内部协调移动和攻击，但不能让两个独立任务拥有者争写身体。

### 3.3.1 全任务发现、选择与认领

用户于2026-10-23同意收口统一任务设计与迁移边界。所有工种共用任务目录、逐NPC选择、唯一认领和执行控制；各业务只提供候选发现、前置条件、行为适配、效果及恢复协议。禁止每工种另建调度器，也不采用一个全局FIFO队列代替逐NPC工作偏好。详细协议见[统一任务细化](2026-10-23-unified-task-dispatch-design.md)，该文从属于本架构，不构成第二权威入口。

公共工作候选在创建时不指定NPC，领取后才建立关联NPC的Job；Order按稳定ID独立于NPC保存。个人吃喝/跟随候选仅对应本人可选，携货归还/炉具监管等责任候选须明确交接；三类均经同一分级仲裁和Session控制。每NPC在常规工作中先按工种0～4（0禁用、1最高）分组，同级再比较连续性、紧迫性、技能、距离和等待时间；普通工作分数不能越过生存优先等级。

TaskDirectory提供候选索引，DispatchCoordinator只裁决分段/岗位槽的唯一分配，不替代效用层或身体控制器。认领、身体授权和资源声明分别处理。候选失效、Job暂停或租约超时不能释放携货、未知效果或持续义务。生产链首版一个活动执行分段，多人协作须显式协调额度及恢复点，不能直接增加并发数。

按2026-10-23在线需求，制作与最低存量统一提交公共Order，不保留普通下单指定NPC选项。配方与技能研习全面回归原版物理书籍与ISReadABook机制：废除制作前插播2秒自学动画。书籍存放在据点书架作为耐用资产轮流传阅，NPC在闲暇或缺配方驱动下去书架借阅；配方杂志整本读完原版引擎写入KnownRecipes方可接单制作，技能书按已读页数线性增加经验倍率，原生支持快速阅读/阅读障碍/文盲等特质。最低存量为阈值+单次量触发器，不能自行选人或直接启动Production。具体批量单位等业务细节在对应设计修订中明确，不沿用冲突旧稿。

UI按需求11.1～11.4消费同一业务命令与只读投影：取消独立物流调度UI，并取消独立的配方字典下单页（下单收敛为仓储点击物品快捷弹窗与原版制作菜单快捷委托弹窗两大轻量入口；据点任务页签聚焦于全据点工单监控与BOM流转）；增强仓储及跨UI最低存量设置、人员详情/全员优先级矩阵、防御岗位和装备策略。旧页不能在数据迁移前直接删除。详见统一任务细化第16节。

### 3.4 小型微观行为树

评审补充（2026-10-23）：公共分配协调器只处理公共工作认领，个人自理与已有Job恢复由本NPC仲裁/控制器直接处理，不重新抢公共槽位。共享资源仍走唯一声明权威。携货挂起后，先恢复/交付/归还/明确交接再领无关普通工作；危险及急救例外，不可达时保留可诊断恢复等待，不永久冻结身体。哨位区分在岗者与唯一替班预约，到岗按岗位版本转移责任。未加载目标退出活跃候选索引，事件或有界低频复验唤醒；公共认领采用最多3项有序候选及预算内回退。详细边界与新增用例见从属细化第17节。

正式采用行为树组合具体行为，不另建与之并行的第二套通用步骤运行器。明确步骤作为可复用动作叶；既有生产/物流状态机先封装为适配叶，逐步迁移。

初期只提供记忆式 Sequence、Fallback、Condition、Action、有限深度 Subtree。等待、有限重试和超时可由动作叶表达。节点结果使用 Success/Failure/Running；条件与候选评估不改变世界，动作叶经获授会话执行真实效果。

保持运行位置，以事件唤醒和有界轮询推进；限制每轮立即完成节点数和子树深度。Fallback 必须等上一分支清理和效果状态允许后，才能尝试替代分支；有不明消耗时进入核对，禁止自动重试或换材料重复消费。

不做图形编辑器、任意表达式 DSL、无界 Retry、任意 Parallel 或运行树整体序列化。生产依赖仍交给 ProductionChainPlan 等业务规划器，行为树不穷举全配方链。不建设全局 GOAP/HTN 搜索器。

### 3.5 原版动作适配

每类动作独立声明启动条件、效果发生时机、停止处理、完成证据和恢复方式；逐动作白名单适配，不能承诺任意原版或模组动作自动支持。

明确区分启动副作用、渐进效果和一次提交效果。进食中断可能已消耗食物，饮水可能已逐步消耗流体，制作停止也可能触发完成回调；不得把取消视作通用回滚，或把回调名称视作成功证据。行为树成功基于物理后置核验。

2026-10-24用户确认的评审澄清：资源认领的逻辑事务不等于原版动作具备ACID事务或通用原子回滚。恢复基于已发生事实、可验证的补偿和必要隔离，不删除后重造原件。身体停止、资产效果已知性和目标是否加载是三个不同维度：目标暂不可观察不直接证明效果未知，也不授权重放；身体已停但资产未知按下节隔离业务并允许安全撤离。新候选选择规则与进行中原件责任的收尾规则须明确区分，规则变化不能令持货责任无恢复出口。实施顺序与验收见[BACKLOG可靠性与扩展任务](../../BACKLOG.md#可靠性与扩展任务优先级2026-10-24用户确认)，本段澄清既有契约，不表示新增恢复能力已实现。

## 4. 交接与过期回调契约

逻辑顺序固定为：提出中断 → 禁止旧流程派发下一动作 → 请求原生停止/到安全边界 → 核对停止状态及已发生效果 → 保存业务恢复点和义务 → 授予新会话。确切接口名可以随阶段设计调整，顺序和职责不能省略。

| 场景 | 处理 |
|---|---|
| 普通任务切换 | 等待有时限的安全步骤边界，再交接 |
| 紧急个人需求 | 按动作类别停止，保留原件托管及恢复点 |
| 即时危险 | 立即请求停止，能确认安全移动后授予撤离，不等待无关归还完成 |
| 同步制作正在提交 | 当前调用返回后核对实际效果；不能用长锁阻塞主线程 |
| 身体停止状态不明 | 保持交接阻塞并诊断，不能同时授权第二执行者 |
| 身体已停止但资产结果不明 | 资产隔离核对；允许已确认安全的撤离，不把 NPC 永久冻结 |

中止是独立协议：requestStop → 停止中 → 已静止或需核对。不能把“正在清理”直接当普通 Failure 让 Fallback 启动下一分支。

动作入队可能立即 begin，停止/清理可能同步重入回调；交接必须防重入，不能在旧清理尚未返回时启动新任务。Lua 队列不含某动作，不等于原生角色已静止；Java stopProbe/moveTo 也影响动作，需统一审查。

过期会话无权继续派动作、清新队列或释放新会话设施。但旧动作已发生的效果仍须按世界身份、任务 ID、动作尝试 ID 归账；重复通知只更新同一事实，不能因为代次过期丢弃事实或重新制作。

## 5. 业务持久化与资源协调

### 5.1 保存和恢复

记录稳定业务步骤名、流程版本、任务 ID、原件 ID、已确认效果、未知效果和清理义务，不保存闭包、userdata 或整个 TimedAction 队列。流程版本变化必须有迁移或明确拒绝/核对路径，不按旧数组下标盲目续接。

保存屏障统一暂停派单与交接，收集各 NPC 状态及原件效果；保存成功后把随从/制作/生活恢复意图转为候选，经一个控制器重新授予执行权。保存失败保留阻塞事实，不自动复用旧检查点。加载后先恢复业务记录与声明，再重建观察和行为树，重验世界条件。

已确认制成的产物只交付；未知提交不得自动重放。正常保存恢复不等于强退事务或零损失保证，后者仍为未验证边界。

保存边界补充（2026-10-23评审吸收）：不得假定OnSave/退出路径还有后续tick。可提前请求的保存先有界停派/停止并收集状态；原生保存回调只同步捕获当下已确认事实，未停稳或提交不明记录恢复意图及UNKNOWN，不等待异步安全边界、不自行取消引擎保存。OnPostSave不单独证明全部文件成功落盘，也不授权直接续工；只有世界仍活跃、业务与原件状态核对通过后，在后续正常tick仲裁恢复。失败保持阻塞。跨文件崩溃原子性仍不承诺。

停止超时进入受控故障处置：禁止旧派发、记录诊断，可调用已适配的强制停止，但超时/clear成功不是停稳证据。复验身体后才允许新会话，未知效果隔离不重放，不默认传送/重置位置。仍有危险时优先处理已确认可安全执行的撤离路径。

在途移动计入当前任务的执行阶段，普通工种优先级变化只触发安全决策点评估，不立即折返；只有经重新验证并成功分配的新工作才允许普通切换。原目标失效则停止并释放尚未生效的分配，保留原件责任；失败候选按版本/条件冷却，危险/急救可越过普通防抖。最短区间与滞后数值由实施阶段验证，不假定固定3秒适用于全部动作。

设施义务以设备及业务为锚点，责任人允许明确转交；生成检查任务时考虑期限、距离、可达性与可接管者。不能让责任人无限远离仍需紧迫监管的设备，也不能派最近者擅自关闭玩家设备。协作阶段须定义参与者预约/就位、各自Session、共同开始条件、取消与超时，不采用一个NPC越权控制另一NPC的主从模式。诊断默认关闭详细轨迹、固定容量并延迟字符串格式化；简单预算计数与轮转可复用，不引入逐次业务调用的长表分配。

### 5.2 原件、槽位与容量

2026-10-24用户批准工单结清清理：公共Order及普通执行Job在完成交付/取消归还、效果已知、原件/容量声明解除、身体会话停止且恢复关系已结清后移除，不永久保留业务历史。暂停、待归还、未知效果和未完成恢复责任继续保留；持续个人自理记录不当作公共工单历史清理。容量限制约束尚未结清的记录，过往完成量不累计占用。公共提交采用最多128条签发/完成技术回执；活动工单重复请求仍返回同一工单，完成后回执内重试只确认原结果，过期请求拒绝重放。仅删除记录，不删除或重造世界原件。实现及验证见[清理实施计划](../plans/2026-10-24-settled-task-retirement.md)。本决定覆盖历史“未授权自动删除已完成记录”的限制，不授权删未知或未结任务。

2026-10-23用户决定取消旧任务存档兼容：共享任务切换不再编写旧单导入转换器，发现旧记录拒绝自动启用并保留原数据；不自动清理NPC携货或世界物品。此决定仅裁剪旧格式迁移，不取消新Job自身的保存恢复、原件义务和唯一资产裁决。实施见[共享Job切换计划](../plans/2026-10-23-shared-job-cutover.md)。

继续扩展 LaborStore/LaborClaims 的唯一协调，禁止另建并行库存账本。多任务挂起需版本化迁移现有 byNpc 单任务索引及“物流/制作只能有一个未完记录”的校验，不能直接绕过。

NPC 持有的材料、工具和产物不能因会话结束或租约超时重新分配。暂停生产和自理任务可以分别声明不同原件。自理不得随意食用另一任务托管的生产材料；需要改变用途时走明确业务转移。新单生产不读取玩家背包，继续复用分类箱过滤、隐私和最终物理验证。

材料、工具、设施槽位和目标容量分别定义释放条件。资源申请固定顺序或有界批量尝试，失败只撤销本次未生效申请，不能释放已持有原件。预留不保证玩家不会改变实际容量；提交前仍需检查。

### 5.3 持续设施和协作义务

炉具监管独立记录设备身份、相关食物、启动归属、责任人/接管状态和下次检查条件。NPC 休息或子树退出后义务仍存在，实际取出/关火通过新任务执行；玩家使用或归属不明时禁止擅自关闭。

固定配方、加料组装和温度过程分别适配。无设施要求的配方不强制找平台。床、饮水点、灶台等以能力、位置和槽位表示，不能全部硬塞进制作平台模型。

2026-10-24用户批准床/沙发以设施候选、唯一预约、到位重验接入个人自理，不建公共工单。整件家具支持公共（默认）、指定稳定npcId专用、禁止NPC三种策略；专用成员缺席不自动开放，玩家不受该策略限制。多格家具归并为稳定整件及部件身份，未验证独立睡位时整件仅一个睡眠预约，休息只占所选部件。选择和执行均检查策略版本、真实玩家占用、唯一声明及原对象身份；政策改变、拆除或失败后先确认NPC停止/醒来再释放。共享短期观察及有界扫描/寻路，失败目标冷却后再选或地面回退；持久化只保存标量身份/位置/版本，不能按同坐标继承替换家具。0.24.3接线及未验证边界见[家具策略证据](../../reviews/2026-10-24/repose-sites.md)，坐卧动画未适配，原生睡眠效果仍待游戏验收。

未来多人协作任务以稳定任务协调各 NPC，不能让一个 NPC 的回调直接接管另一个 NPC 的身体。死亡、失联和未知货物保留恢复责任，不凭空重造或自动释放。

## 6. 观察、性能与诊断

共享库存、设施和任务候选索引。事件失效配合分散的低频采样；原版并非所有状态都有可靠事件，不承诺纯事件驱动。区分已知可用、已知不存在、未加载未知、观察过期；未知不等于零库存，不能因此重复生产。

扫描、寻路请求、规划、设施检查和节点推进分桶计费，复用轮转并增加全局预算协调。危险有快速通道；预算不足是等待，不是失败或目标不存在。Lua 负责策略、树编排和恢复，Java 维持载体/移动边界；批量读取等在测量后再决定下沉。

记录有上限的决策轨迹：当前任务、候选拒绝原因、中断原因、恢复去向、原件位置、交接耗时和各预算耗用。主要界面展示玩家能理解的状态，机器 ID 留诊断详情。隐性感染等遵循游戏可观察性，不能全知读取后公开。

## 7. 迁移顺序与阶段验收

| 阶段 | 内容 | 必须确认 |
|---|---|---|
| P1 控制权和兼容迁移 | 控制器、停止/效果协议，接入 Work/Companion/Production、诊断及保存入口；旧流程作为适配叶 | 独占、重入、过期回调、同 tick 竞争、保存后唯一恢复；双 NPC 一人切换不影响另一人 |

实现按完整功能切片交付，不整体重写现有功能。按风险做相关最小回归，修改 Lua/Java/文档分别执行项目规定检查；不重跑无关历史全套。静态、宿主、单机实测、故障恢复和性能分别记录，没运行写未验证。

以下场景是设计验收目标，当前均未通过本架构实测：制作取料后口渴；制作提交时遇敌；吃到一半中断；玩家移动工具或改变容器；保存后随从/制作竞争；NPC 离开但炉具仍需监管；协作被危险打断；目标箱未加载。

如果原型证明某类动作不能可靠停止或核对，限制该动作自动化并报告原因，不靠更换框架名称掩盖。预算数值、停止确认时延和 NPC 规模必须测量，不能在设计阶段宣称达标。
