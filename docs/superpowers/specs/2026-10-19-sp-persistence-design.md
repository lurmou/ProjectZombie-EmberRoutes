# 单人 NPC 保存与恢复设计（0.5.0）

状态：按用户“继续下一步任务”实施；仅单人，一名实体。基线沿用 B42.21.0 / ZombieBuddy 2.3.4。

采用原版 `IsoPlayer.save(ByteBuffer,false)` / `load(ByteBuffer,249,false)`，完整原版人物负载随当前世界的 GlobalModData 保存。相比逐字段重造，能保留身体、技能、描述、装备及嵌套物品实例；相比独立文件，避免人为制造第二套提交时序。仍不承诺断电原子性，世界文件与全局数据须作为整体备份恢复。

封装包含格式版本、游戏 JAR 哈希、世界路径标识、NPC UUID、原坐标、驻点与意图、库存 ID 清单、原版字节和 SHA-256。4 MiB 原版负载、4096 件物品、16 层嵌套限制；超限阻塞，不截断。每次 OnSave 先取消动作、清理本模组夹具、停止路径，再生成检查点。保存失败写阻塞标记，禁止回退旧人物。宏观商队与工作队列尚未持久化，不能重放半截搬运。

OnGameStart 后只自动尝试恢复一次。当前已有实体、格式/哈希/世界不符、校验失败、人物死亡、库存不匹配或原坐标方格未加载时均拒绝，不新造替代品、不自动选旧快照。可到原位置显式重试。恢复先在未加入世界的对象上加载、验证，最后取得会话所有权并加入世界；不占真实玩家槽位，始终恢复相机与 IsoPlayer.instance。

驻点按同一 UUID 恢复；FOLLOW/RETURNING 保存意图，加载后用当前本地玩家重新验证和建立路径。其他工作与手动坐标移动恢复为 HOLD。保存时保留活人物继续运行。明确删除或死亡后，下次正常世界保存写空记录，不能从旧快照复活。保存记录不可在存在活人物时手动恢复，防止重复实体。无存档时保留现有生成操作；有待恢复/阻塞记录时禁止用生成绕过。

边界：这是正常世界存取协议；不承诺任意模组私有字段、未序列化的引擎状态、全地图物品 ID 去重或崩溃无损。当前没有离线劳动、离场虚拟化、多 NPC 或 MP 支持。同进程换世界只在原版替换世界实例、清空旧对象列表且所有旧chunkMap已置null后释放旧引用；不调用已销毁世界的原生人物方法，条件不足则阻塞。

补充：分块16000字符避免原版short字符串长度溢出；附加保存原版未覆盖的挂载槽位到物品ID关系；恢复需要玩家在16格内。增加可跨存档样本和正常保存整个世界的验证菜单，已有物品不被替换，外来内容或穿戴样本阻塞样本清理。烧伤中的火焰状态与乘车角色暂拒绝快照。

验收：纯逻辑覆盖损坏、截断、超限、版本/世界不符、重复恢复与状态转换；Lua 覆盖保存前交接与恢复意图；编译、preflight、release-check；实机集中验证跨完整退出、嵌套物品/身体/装备、驻点/跟随、重复恢复、保存继续游玩、删除后重载、远处方格拒绝及失败记录。实机未执行不得写通过。
