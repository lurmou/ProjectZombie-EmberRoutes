## 实现

- Java `CarrierRuntime` 每人独立持有会话、退场、路径门禁与恢复状态。`ProbeRuntime` 维护稳定 ID/handle 索引、选择适配与最多 8 会话的共享生命周期轮转预算；不会自行重复调用 NPC 的引擎 update。新 API 的动作按 ID 绑定，选中变化只影响后续用户命令。世界和 cell 均参与清理边界；基线拒绝不能绕过到新增 NPC。
- `ProbePersistence` 按 slot 存检查点，旧 v1 只迁入 v2 的 legacy 记录一次。跨记录检查 NPC/物品 ID 冲突，正常保存仍先停止所有 Lua 执行者。跨记录校验按受控发布版本缓存，避免逐人恢复时重复解码全部记录；每个目标仍独立校验检查点校验和、存档/JAR 基线和原生载入结果。写入拒绝会阻止混合旧记录重放。
- `LaborStore` 是唯一工单权威，旧 `job` 单次迁移后删除，按 npcId/taskId 保存纯标量意图。整本账通过校验后才发布内存索引；加载时 RUNNING 转 PAUSED，不自动重放动作。
- `LaborClaims` 在产生物理效果之前排他认领全部物品 ID，并按当前单件重量预留目标容量。物品使用哈希索引，容量按容器维护总预留量和任务项，普通查询/增减/续代不扫描其他工人或全部容器。认领先整体检查再提交；任务代次使旧回调失效。暂停保留物品归属，持货/位置未知时保留容量声明；已核对原件放入目标后才释放该声明。容量声明随纯标量任务保存，重载重建。每次效果仍检查原对象/位置/规则和原版容量，不能阻止玩家或其他模组写库存。
- `WorkAgent` 每 NPC 一个执行器；`Work` 为选中适配及共享调度门面。每事件最多 4 个执行器，各自约 100ms 到期；后台盘点切片每人最多读取 32 件，因此此项最多 128 次物品读取/事件。初次用户开单/续工仍同步核对最多 3×2000 件，原单上限 30 件。预算限定工作单位，不保证耗时或人口规模。
- 随从按 NPC 独立上下文，共用预算；旧动作/17 步诊断夹具仍保留单批次，但命令取消/清理和移动按拥有者隔离。菜单增加选择和生成第二人；正式工单源/目标按 NPC 保存。仓储只读契约保持。

## 后续边界

先完成两个真实 NPC 的集中实测，再在这一内核之上接自动多仓分拣。物品清单和任务种类目前是显式搬运消费者，不宣称通用 BOM/调度 AI 已完成。当前 NPC 卸载/死亡/失联会暂停对应工单并保留未知货物声明，尚无自动转单协议。单条检查点编码和世界保存仍同步，单记录恢复也有成本；不承诺大人口性能或跨世界文件的崩溃原子性。未知/冲突记录拒绝执行，不能用新造同类物品补账。
