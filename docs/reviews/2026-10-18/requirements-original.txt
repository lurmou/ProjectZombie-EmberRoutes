# 《Project Zomboid》社区网络与商队贸易系统设计规格书 (GDD & TDD)

## 1. 项目概述与核心目标

* **定位**：基于《Project Zomboid》（以下简称 PZ）深度拓展的中后期经营玩法 Mod。
* **设计灵感**：融合《颂钟长鸣》（Bellwright）的据点网络协作机制与《环世界》（RimWorld）的清单式交易台交互。
* **核心目标**：彻底解决 PZ 原版中后期玩家资源严重过剩、安全区无挑战、目标感丧失的硬核痛点。
* **核心循环**：

$$\text{资源搜刮/工农业产出} \rightarrow \text{满足据点生存消耗} \rightarrow \text{据点升级扩展} \rightarrow \text{组建商队外销调配} \rightarrow \text{换取工业蓝图与稀缺物资} \rightarrow \text{据点热度上升引发周期防御}$$

## 2. 待本地工程调研专项（Open Technical Investigation）

### 2.1 调研背景与技术矛盾

* **诉求**：拒绝使用“僵尸换皮”方案制作人类 NPC。计划通过继承 `IsoPlayer`（或 `IsoGameCharacter`）构建具象化人类实体 `IsoNpc`，具备穿衣、负重、射击、近战及原版 `TimedAction` 交互能力。
* **矛盾**：
1. 若不走输入流控制，强行挂载动作易导致“**仅播放原地踏步动画、无物理位移**（Root Motion 与物理坐标更新脱节）”。
2. 若继承 `IsoPlayer` 并劫持物理输入流，在多人模式（MP）下会直接撞上 PZ 底层的网络拓扑硬编码（`IsoPlayer` 强绑定 `UdpConnection`、SteamID 及客户端本地渲染视口 `IsoCamera`，极易导致客户端瞬移、空指针 NPE 崩溃或反作弊校验踢出）。



### 2.2 本地代码库核查目标 (Checklist for Local Reviewer)

1. **输入与物理位移解耦验证**：
* 检查 `zombie.characters.IsoGameCharacter` 中 `getPathFindBehavior2()` 的实际调用链。
* 排查在无硬件输入（`Core.getInstance().getKey()`）介入时，手动赋予 `character.setnx()` / `character.setny()` 并触发 `character.updateMovement()` 是否能绕过动画原地踏步的 Bug。


2. **多人网络拓扑与实体假人注入（Fake Connection）**：
* 检索服务端包处理器中是否有校验 `IsoPlayer.OnlineID` 对应底层 Socket 的断言。
* 评估基于 **ZombieBuddy** 或 **Bytecode Mixin** 在内存中为 `IsoNpc` 伪造虚拟连接的可行性；或论证是否应降级为继承 `IsoGameCharacter` / 原版未启用的 `IsoSurvivor` 骨架。


3. **TimedAction 队列复用性验证**：
* 检索原版所有的 `ISBaseTimedAction`（如 `ISPlantAction`, `ISChopTreeAction` 等）对入参 `character` 的强制类型转换是否仅限制在 `IsoGameCharacter`，是否存在针对 `IsoPlayer` 的独占向下转型（Downcasting）。

## 3. 劳动力与据点生产体系

为了杜绝高频重寻路造成的性能雪崩与联机卡顿，劳动力岗位执行“**宽泛聚合**”设计。

### 3.1 四大职能大类

| 岗位分类 | 职责范围 | 交互逻辑 | 产出物/消耗物 |
| --- | --- | --- | --- |
| **农牧后勤 (Farmer)** | 耕作、浇水、施肥、收割、就近打水 | 绑定指定农田地块（Zone）。优先消耗种子袋与水桶，将收获物送回粮仓。 | 产出：鲜蔬、草药<br>

<br>消耗：水、种子、农具耐久 |
| **工匠拆解 (Crafter)** | 批量初级制造、指定垃圾箱拆解、废料加工 | 绑定加工台与拆解容器。监控输入箱，产出物自动堆叠至输出箱。 | 产出：木板、钉子、金属板、布条<br>

<br>消耗：原木、废铁、脏衣服、工具耐久 |
| **巡逻哨卫 (Guard)** | 警戒哨位、闭门、射杀/刺杀警戒圈内散怪 | 绑定指定巡逻路径节点或瞭望台。进入警戒范围的僵尸触发交战逻辑。 | 产出：据点安全度（降低热度）<br>

<br>消耗：弹药、近战武器磨损、医疗品 |
| **医疗内勤 (Care/Cook)** | 大锅饭料理、伤员包扎换药、发电机添油 | 绑定营地火炉/医疗箱。按周期将食材加工为无衰减的高热量大锅饭。 | 产出：群体饱腹度与士气 Buff<br>

<br>消耗：原料、烹饪燃料、消毒水/绷带 |

### 3.2 离线与未加载区块计算（双层架构）

* **宏观虚拟层（Macro Virtual Layer）**：当据点区块无任何真实玩家加载时，注销全部物理实体，转入纯数学结算。以游戏内每 1 小时为 1 个 Tick，根据各岗位 NPC 技能点、工具可用度、库存原料进行产出与消耗结算。
* **微观实体层（Micro Instance Layer）**：当任意玩家进入据点加载半径（Loaded Chunk），按后台数据结构实例化出对应外观的 `IsoNpc`，并将其就近分配到对应的工位上执行循环动画。

## 4. 贸易与经济结算体系（环世界式交易台）

### 4.1 计价模型与以物易物（Barter Balance）

* **无信用纸币**：废除原版无用的法币，采用纯物品价值点数（Value Points）平衡体系。
* **天平平衡设计**：

$$\text{Balance} = \sum (\text{玩家提供物品} \times \text{玩家基础估值} \times \text{据点收购系数}) - \sum (\text{据点索取物品} \times \text{据点基础估值})$$



仅当 $\text{Balance} \ge 0$ 时交易按钮可点击。多余的盈余差额可选择抹零、或自动按固定汇率换算成**硬通货找零**（优先级：9mm 子弹 > 盒装香烟 > 盒装抗生素 > 密封汽油罐）。

### 4.2 阶梯式需求弹性衰减（反刷机制）

每个城镇据点维护独立的需求系数字典 `DemandModifiers`：

* 当某种物品在 24 小时内向该据点输入超过基础阈值（Threshold），收购系数从基准 $1.0\text{x}$ 线性跌落（最低跌至 $0.2\text{x}$）。
* 物品需求以游戏日（Game Day）为周期平滑恢复，恢复周期为 3~7 天。
* 各镇具备专属**固定收购倾斜**（如西点镇汽油收购系数常驻 $1.5\text{x}$，马尔德劳木材收购常驻 $0.6\text{x}$ 但钉子收购常驻 $1.4\text{x}$）。

### 4.3 联机防刷与并发保护（Exclusive Transaction Lock）

```
[客户端 A: 请求与西点镇商人交易] 
        │
        ▼ (ClientSend: RequestOpenTrade)
[服务端验证] ── (若该据点已被锁定) ──> [返回客户端 A: "商人正忙，请稍候"]
        │
        ▼ (未锁定: 写入 LockHolder = PlayerA_ID)
[服务端下发最新库存镜像并锁定据点]
        │
[客户端 A 调整滑块并提交交易确认] ──> [服务端验证库存有效性并原子性扣改]
        │
        ▼ (ClientClose: ExitTrade)
[服务端解锁据点 (LockHolder = null)]

```

## 5. 商队调度、大地图状态机与遭遇战

### 5.1 行程状态机设计

商队移动基于全图主干道预设节点网格（Highway Node Graph）推进，不占用真实的实体物理寻路。

```
              ┌──────────────┐
              │ IDLE (待命)  │
              └──────┬───────┘
                     │ (整备完毕: 人员/载具/口粮扣除)
                     ▼
              ┌──────────────┐
              │   PREPARING  │
              └──────┬───────┘
                     │ (载具物理脱壳, 转入后台数据流)
                     ▼
              ┌──────────────┐  遇险判定 (概率触发)  ┌──────────────┐
              │    MOVING    │ ──────────────────> │   BESIEGED   │
              └──────┬───────┘                     └──────┬───────┘
                     │                                    │ (24h 倒计时)
                     │ (抵达目标城镇)                      ├── 玩家肉身前往清怪
                     ▼                                    └── 超时: 后台数值强平
              ┌──────────────┐                            │
              │   TRADING    │                            │
              └──────┬───────┘                            │
                     │ (交易完成)                         │
                     ▼                                    │
              ┌──────────────┐                            │
              │  RETURNING   │ <──────────────────────────┘
              └──────┬───────┘
                     │ (返回本阵营据点)
                     ▼
              ┌──────────────┐
              │  UNLOADING   │ (车辆物理重构, 货物入库)
              └──────────────┘

```

### 5.2 遭遇战机制（后台兜底 + 玩家肉身救援）

* **被困状态（Besieged）**：商队抛锚或遭伏击，暂停前进，进入 24 小时（游戏内时间）解围倒计时。
* **无线电告警**：同阵营玩家短波电台收到警报，并在大地图上高亮红色标记点。
* **双结算通道**：
* **玩家亲临解围**：玩家在时限内驱车进入该标记点，触发微观实例生成（生成受损车辆、掩体防守的护卫 NPC 与固定规模尸潮）。击杀全部威胁后，商队直接解除脱困状态。
* **后台数值结算**：若倒计时结束无玩家前往，服务端执行战斗力公式对冲：

$$\text{胜率} = \frac{\text{护卫总战力} \times \text{车辆防御系数}}{\text{遭遇威胁强度}} \times 100\%$$



根据骰子点数扣减护卫生命、货物丢失百分比或判定全军覆没。

## 6. 据点所有权、多人领地与边界容灾

### 6.1 核心载体：市政控制台（Town Core）

* 玩家必须制造并安放物理家具“市政无线电指挥台”以确立领地，以此为中心划定正方形边界。
* 权限基于阵营 ID（Faction ID）绑定，分为四级：
* **领袖 (Leader)**：领地迁移、建筑拆除、核心升级、宣战结盟。
* **官员 (Officer)**：派遣商队、调动公共武装、招募/指派 NPC。
* **居民 (Resident)**：安全区进出、使用指定存储箱与床铺。
* **访客 (Visitor)**：仅有通行权，无法开箱或干涉 NPC。



### 6.2 离线保护与防拆机制 (Offline Protection)

* **低功耗维持模式 (Stasis Mode)**：当阵营内所有玩家离线超过游戏内 24 小时，据点自动进入冻结维持态：
* 农工生产暂停；
* NPC 粮食与水消耗率降低至 $10\%$；
* 商队若在归途中，继续跑完后台节点并安全自动卸货入库。


* **领地防破坏**：非本阵营玩家在未处于宣战状态下，在领地范围内禁止使用大锤拆墙、撬门窗或倾倒燃油放火。

### 6.3 极端容灾机制 (Fail-Safe)

1. **载具虚实转换防穿模**：
* 商队派出时，载具从物理地图中移除，序列化存入 `ModData`；
* 商队返回时，系统检测原停车位是否被杂物或外来车辆阻挡。若阻挡，自动转移至备用溢出点，若无空间则将货物强行卸至领地收货箱，载具转为“待提车”状态，避免物理弹飞 Bug。


2. **服务器崩溃重启保护**：
* 每次启动全局数据加载时（`OnInitGlobalModData`），服务端主动扫描所有处于非 `IDLE` 状态的商队。若状态异常，回滚至最近经过的路线节点（Checkpoint Node），杜绝货物与人员蒸发。


3. **市政控制台物理烧毁**：
* 控制台因火灾或外力损毁后，据点领地数据不会被删除。系统记录“核心失联”，在游戏内 3 天宽限期内重新制作并安放控制台即可恢复全部设置与领地范围。


4. **领袖硬核阵亡继承**：
* 所有权绑定阵营而非单次生命周期。领袖死亡重开角色后，凭阵营密码或历史绑定的 SteamID64 在控制台输入凭证即可重置管理权限。

## 7. 社区升级与科技树体系

升级采用“**四维基础建材投入** + **对应城镇专属技术蓝图**”的双轨驱动。

```
[Level 1: 简易避难所]
  │  要求: 100木板 / 4盒钉子 / 基础水源
  │  解锁: 农牧初级自给、1名可用NPC工位
  ▼
[Level 2: 筑垒村落]
  │  要求: 300木板 / 50金属管 / 发电机 / 《马尔德劳工业初探》蓝图
  │  解锁: 批量拆解台、大锅饭烹饪、开启首条商队线路 (支持轻型皮卡)
  ▼
[Level 3: 区域贸易枢纽]
  │  要求: 500防空木墙 / 200废金属 / 自动化电气元件 / 《西点军备总录》蓝图
  │  解锁: 车队改装车间 (重型卡车解锁, 载重+300%)、商队并发上限提升为2条
  ▼
[Level 4: 废土城邦]
  │  要求: 1000高级建材 / 工业水塔 / 《路易斯维尔精炼工业手册》
  │  解锁: 弹药复装车间、哨位集中警报汽笛、全自动化集水净化闭环

```

* **热度平衡机制（Heat & Siege）**：
社区每提升一级、工农业机器越多、商队出入越频繁，据点的每日基础“热度值”越高。热度累积至阈值将直接引来周边超大范围的**尸潮围攻（Siege Event）**，迫使玩家将贸易获利的盈余转化为防御工事与守卫弹药消耗，杜绝挂机刷资源。
