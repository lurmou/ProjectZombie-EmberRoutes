## 1. 完成定义（DoD）：改过任何 `.lua` 就必须跑，并且必须把原文贴出来

```powershell

```

**这一条就是全部门禁**，六层按序跑、失败累计、一次看完：

| 层 | 查什么 |
|---|---|
| `lua_lint.js` | 语法 + 作用域 + 旧的行级规则 |
| `pz.mjs lint` | 15 条**规范驱动**的结构性规则（捏造 API、手工塞 children、漏调父类…），**补 `luac`/`luals` 之盲**（官方工具不查"漏调父类"这类框架规则）；**非** `I.7` 里「禁自写 linter」所指的"替代官方的语法/类型检查器"，与该项裁定不冲突 ｜ **含所有默认关闭的规则**（名单现场读 `lint-rules.json`，不手抄） |
| `pz.mjs mine --check` | **从原版语料挖出来的不变量**：漏 `setmetatable`（静默失效）、帧里现算可缓存 API、new 了窗口不 `addToUIManager`、new 完直接用没挂载 |

| `pz.mjs luals` | lua-language-server + Umbrella 类型桩，抓 PZ API 误用 |
| `pz.mjs fresh-smoke` | **预计算索引新鲜度**（★ 2026-10-14 新增第 5 层）：api-symbols / resolve-index / event-symbols 等产物比来源旧 = 「原版定义 0 处」这条铁律在读旧事实，前面四层会拿着过期判据下结论。定位不到游戏目录时显式跳过。修：`node .workbuddy/tools/pz.mjs index-rebuild`（7 个索引按依赖顺序一键重建，约 18s） |

## 2. 查证纪律（最贵的三次返工都出自这里）

- 任何 API 先查：有 `pz_lookup` 工具时用它；**当前 WorkBuddy 环境无该工具**（它是 DSH 插件 `pz-spec-sidebar` 提供的）⇒ 用等价 CLI **`node .workbuddy/tools/pz.mjs ask <API>`**（含签名/继承/定义/真实调用点，与 `pz_lookup` 同结论）。
  **返回"原版定义 0 处"= 这个 API 不存在**，不许凭记忆写。规范全文用 `pz_spec_read`，无该工具时**直接读** `.workbuddy/specs/<rel>`；原版源码片段用 `pz_source`，无该工具时用 Read 读对应文件行。
- **最小宽高是字段不是方法**：`o.minimumWidth = 300` / `o.minimumHeight = 200`。
  原版**没有** `setMinWidth` / `setMinHeight`（定义 0 处、调用点 0 处）；夹取在 `ISUIElement:onResize()`（`ISUIElement.lua:563`）。
- 新增能力先搜原版 `<游戏目录>/media/lua`，有等价实现就复用并标出处（见 `I.5` 编码红线）。

## 3. UI 生命周期速记（完整版见 `checklists/ui-panel.md`）

- 两段式：`X:new(...)` → **必须** `:initialise()` → `:instantiate()`（后者内部自动调 `createChildren`，别手动再调一次）。
- `new` 里 `Parent:new(...)` 之后**必须**补 `setmetatable(o, self); self.__index = self`；漏了 → 你写在子类里的 `render`/`createChildren`/`onClick` **全部不会被调用**（静默，不报错）。
- 子控件只能 `self:addChild(child)`（禁止 `self.children[i] = child`）；重写 `prerender` 第一句必须调父类。

## 4. 写盘门禁（自动生效，不需要你记得调用）

`.lua` 与 `*.md` 一落盘，harness 就会跑一次检查（Lua = **完整档 lint**，含全部默认关闭的规则；
Markdown = `pz-doclink` 断链 + 头部格式），结果在**下一次**工具调用时回注到你的上下文里，带「正确写法 + 后果 + 规范路径」。

- 机制：`.claude/hooks.json` → `.workbuddy/hooks/gate.mjs`。配置在 DSH 的 `work` profile。
- **它是异步的**：落盘后立刻返回（~200ms），后台跑完（~4s）下次才提示。所以
  **看到提示时，问题已经在上一轮写下的文件里了** —— 直接修，别重新跑一遍检查。
- 门禁失败一律 fail-open（不阻断你的工作）。**"没看到提示"不等于"没问题"**，
  收工仍要跑 §1 的 `preflight.js`。
- 自检（怀疑门禁失效时跑）：`node .workbuddy/tools/pz.mjs hook selftest`
  ⚠️ 这条存在是因为门禁**出现过两次静默失效**：BOM 让解析器崩（规则全不跑但报"0 命中"）、
  钩子读了一个不存在的环境变量。两次都不报错。

## I.2 目录结构铁律（B42 规范）

- `mod.info` **必须进版本文件夹 `42/`**（非 mod 根）。
- **id 全局唯一且只一份**：删除 B41 残留的根 `mod.info`，避免与 `42/mod.info` 的 id 冲突——冲突会让 MP 命令的 `module` 串匹配不上，联机直接废。
- lua 三端分目录：`42/lua/{client,server,shared}`。这是**加载域分隔**，不是三份拷贝；同一段逻辑只放它该在的那一侧。
- 资源：贴图 `textures/`、UI `ui/`、音效 `sound/`、脚本 `scripts/`、翻译 `shared/Translate/{CN,EN}/`。
- 版本文件夹 `42` ≡ 42.0；次要版本无效（`42.0.5` 视作 `42.0`）。
  > ⚠️ **本条后半句已证伪（2026-09-08，见 `../KuKu'sWeapon/docs/weapon_mod_kit.md` §1.2）**：次要版本夹**有效且互相独立**。
  > 反证：① pzwiki `Mod structure#Build_42` 目录树原文含 `42.1/` 与 `42.1.5/` 两个独立版本夹；② PZ-API-Docs `modinfo.md` 原文 "multiple versions of your mod (e.g., 42.12 and 42.13)"；③ 参考模组 Legendary Tactical Weapons 实装 `42.15/` + `42.20/`。
  > **现行规则**：按「主版本.次版本」匹配，取不高于当前游戏版本的最高匹配夹（当前 42.20.4 → 用 `42.20/`）。`mod.info` 与 `media/` 同级、放版本夹内。

## I.3 联机（MP）架构铁律（从一开始就做）

- **服务端权威**：物品的扣减/产出只在 **server** 端（`OnClientCommand` 回调里真正改），client 端改世界/物品在 MP 无效。
- client 只发意图：`sendClientCommand(modId, "Cmd", args)`；`module` 串**必须 == mod id**。
- server 文件顶部 `if isClient() then return end`；`Events.OnClientCommand.Add(fn)`，回调签名 `(module, command, playerObj, args)`。
- **client→server 直接用回调第 4 参 `playerObj`**，通常不必塞 onlineID；仅 server→client 或指代第三人时才用 `getPlayerByOnlineID(id)`。
- 改对象 ModData：`obj:getModData()` 写 → `obj:transmitModData()`（**大写 D**，必须在 `isServer()` 下调用；勿与 `IsoGridSquare.transmitModdata()` 小写 d 混淆）。
- **服务端须用 `playerObj` 重查真实状态**（背包/世界），不依赖 args 声称——args 可能过时。

## I.11 预计算索引与门禁路由（★ 2026-10-14 新增）

> 工具链把重活预计算成 JSON，侧边栏与 agent 工具**只读产物、不重算**。代价是**产物会静默过期**，
> 而「原版定义 0 处」这条铁律读的正是它们 —— 过期时正确的代码会被判成不存在。

- **发现过期**：`node .workbuddy/tools/pz.mjs fresh-smoke`（判据 = 产物 mtime ≥ 来源 mtime，不做内容比对）。
  **已挂进 `preflight.js` 第 5 层**（2026-10-14）：发布前必过，只跑 preflight 的人从此能收到索引过期告警。
- **一键重建**：`node .workbuddy/tools/pz.mjs index-rebuild`（7 个索引按依赖顺序跑完，实测全量约 18s）。
  `--fast` 跳过 umbrella（最慢、最少变）· `--only resolve,coverage` 单跑几步 · `--list` 列步骤 · `--dry` 预演。
  ⚠️ `pz_member_index.js`（Java 暴露面）由 DSH preset 生成，**不在** rebuild 职责内；它变了只需重跑 api-symbols 那步。
- **Python 侧解释器**：rebuild 调 `build-lua-index.py` / `build-api-symbols.py` 时取 `PZ_PYTHON`，缺省 `python`。
- **权威源优先级检索入口** → `.workbuddy/retrieval.md`（`I.1` 已挂指针）。
- **门禁路由（★ 2026-10-14 新增）**：`node .workbuddy/tools/pz.mjs gate <lua|md|publish|spec|regression|all> [mod目录]`
  —— 按改动类型一条命令跑对应门禁组合（`--list` 看类型、`--dry` 预演、`--strict` 核对零注释、`--fast` 跳过最慢回归）。
  **它是路由层不是新门禁**（只 spawn 既有工具，自身零检查逻辑）；`preflight.js` 仍是 Lua 门禁的唯一真相。
