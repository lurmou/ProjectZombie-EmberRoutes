# 据点控制台与工单监控第一轮（0.22.16）

2026-10-23。依据[已确认UI设计](../../superpowers/specs/2026-10-23-settlement-ui-design.md)及[本轮计划](../../superpowers/plans/2026-10-23-settlement-ui-round1.md)。用户明确批准将新外壳和工单监控前移；P1仍未通过实机验收。

## 已接入

- 主控制台仅开放仓储总览、工单监控；初始尺寸按字体约48×32行尺度并限制在屏内。导航、内容和底栏分区，不展示未接后端的人数、发电机或防御读数。人员/防御不放空按钮。
- OrderMonitorService从现有craftProbes.byNpc与labor.tasks生成标量副本，不新增持久Order表、公共候选池或调度器。以稳定工单ID选中，命令携代次重验，再交给CraftingService/Work；选择其他NPC不会改写操作目标。
- 支持未完、执行/停止中、等待、暂停、需核对、结束的当前记录筛选；宽屏列表/详情并列，窄屏切换。展示执行者、人员行为、阶段、已制作/已交付、链计划和原件ID。链计划明确仍为单工匠执行，不虚构多NPC协作或倒计时。
- Runtime只增加精确Job的只读状态查询与离散变化通知。停止未确认显示停止中；跟随与工单暂停分开；制作/搬运未知效果保持核对状态。无Java/载体时仍可查看保留记录。
- 旧制作/存量及物流设置移到监控内兼容入口，原菜单/仓储跳转仍可达。未完搬运不在物流工人池内也不消失；无settlementId的手动搬运要求两端都在本据点。
- 订阅复用既有CraftingService合并通知，不增加每帧库存/角色轮询。隐藏/关闭释放视图、拒绝迟到回调，后台业务继续。页签方向循环使用非负索引，兼容Kahlua余数语义。

## 当前限制

这是旧Job兼容监控，不是公共Order已实现。公共下单、优先级认领、Stock迁移、网格/收藏/液体、人员及防御仍待对应业务阶段。本轮不扩展旧配方浏览，也未删除旧任务恢复页。

取消沿用现有能力：运行中的制作先暂停，确认停止后可取消处理余料；未知提交只核对/交付，不重新制作。搬运支持暂停/继续原交付，其他恢复走兼容页，不提供虚假的一键归还或抹除资产。完整公共Order取消事务尚未实现。

原件列表是账本记录，已交付项明确标识，不能将所有记录解释为仍被锁定库存。结束列表仅含当前账本留存记录，不是完整历史。旧配置页仍可加载配方目录，默认监控不加载它。
