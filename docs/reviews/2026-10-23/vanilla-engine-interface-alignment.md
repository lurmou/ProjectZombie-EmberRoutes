# 原版引擎底层接口与机制对齐审查

> 日期：2026-10-23｜状态：用户已确认审查结论｜适用：P2生活自理、P4烹饪、P5农业/医疗/哨卫等全工种设计与实现。

## 1. 依据与背景

在审查在线需求文档（v3.2 修订稿）关于“2秒看图纸自学”的设计缺陷后，针对需求文档中多处脱离 Project Zomboid 底层真实 Java/Lua 接口的浪漫主义假设，进行了全面技术核查与边界纠偏。

用户于 2026-10-23 明确确认：
- **医疗伤病处理严格采用“两阶段模型”**：即时止血属于 **NPC 自我照顾（Self-Care）模块**，NPC 优先就地使用任何可用止血物资保命；止血完成后再评估深层伤情，判定是否需要医生进行专业缝合、消毒或夹板治疗。
- **其余 6 项原版底层机制纠偏全部认可**，作为后续各工种适配原版 TimedAction 与行为树的硬性基线。

## 2. 七项原版机制与接口对齐细则

### 2.1 医疗伤情两阶段闭环（自我照顾止血 + 事后专业治疗）

* **错误设计假设**：伤员出现流血时，远处的医护 NPC 立即中断一切劳作，拿取药包赶往病榻施救。
* **引擎物理事实**：颈部/大动脉裂伤在原版中失血致死时间在 15~20 秒以内。远距离医生跑图根本无法应对秒级致死出血。
* **对齐规范**：
  1. **第一阶段（就地止血，归属于 NPC 自我照顾模块）**：
     * NPC 受到流血伤害后，一旦脱离直接致命交火，最高优先级触发**个人维生自救**。
     * 就地使用背包内任何止血物品（医用绷带、干净布条，紧急时允许撕衣服制作脏布包扎）。优先止住大出血，将生命线拉回安全区间。
  2. **第二阶段（伤情后置核验，归属于公共医疗任务）**：
     * 止血成功后，NPC 评估自身 `BodyPart` 属性：
       * 是否有深裂伤待缝合（`deepWounded` $\rightarrow$ 需缝合针/吸收线，`ISStitch`）；
       * 是否有弹片/玻璃残留（`haveBullet` / `haveGlass` $\rightarrow$ 需镊子/手术钳，`ISRemoveBullet`）；
       * 是否有骨折（`fractureTime > 0` $\rightarrow$ 需夹板，`ISSplint`）；
       * 伤口是否感染需消毒（`infected` $\rightarrow$ 需酒精/消毒水，`ISDisinfect`）。
     * 若存在需要高阶医疗技能的复杂伤情，伤员走向医务病床休养，同时在公共任务池发布**专业医疗护理单**，由医护人员前来进行系统治疗并换药。

### 2.2 农业系统：接驳原版 `SFarmingSystem`，废除臆造的 `IsoPlant`

* **错误设计假设**：农夫调用 `ISDigAction` 真实修改 `IsoPlant` 水分与状态。
* **引擎物理事实**：PZ 中不存在 `IsoPlant` 对象。地里的农作物本质是地面普通 `IsoObject`，所有物理数据（水分 `waterLvl`、生长阶段 `nbOfGrow`、病虫害 `diseaseLvl`）全托管在原版 Lua 全局系统 `SFarmingSystem.instance:getLuaObjectAt(x, y, z)`。
* **对齐规范**：
  * 翻地调用 `ISShovelGround`；
  * 播种、浇水、收割统一通过 `SFarmingSystem` 提供的全局接口操作 `farming_vegetableconf.props`；
  * 农夫必须读取 `SFarmingSystem` 的真实水分与生长时间，严禁绕过全局系统直接操作地表瓦片。

### 2.3 烹饪系统：严格拆分“配方冷备料”与“炉灶容器渐进热力模拟”

* **错误设计假设**：厨师站在炉灶前执行 `ISCraftAction` 一步到位合成出热料理。
* **引擎物理事实**：PZ 炉灶（`IsoStove`）是具有热力学模拟的特殊 `ItemContainer`。烹饪是由冷热两个阶段构成的物理过程。
* **对齐规范**：
  * **第一阶段（备料冷加工）**：使用厨刀/容器将食材组合为未烹饪的汤、炖菜、派等（调用原版配方 `ISCraftAction`）；
  * **第二阶段（热力加热与烘烤）**：将未熟料理通过 `ISInventoryTransferAction` 放入 `IsoStove`；开启加热（`stove:setActivated(true)`）；炉灶内部物品随物理 tick 逐渐累加 `cookingTime`；
  * **取餐与关火闭环**：当物品达到 `Cooked` 状态时，厨师取回食物并关闭炉灶，严防超时变为 `Burnt` 引发火灾。

### 2.4 水利与卫生：清除生水洗涤中毒伪规则，避免浪费净水

* **错误设计假设**：洗衣服与洗澡必须严格使用纯净水，严禁使用雨水桶生水防中毒。
* **引擎物理事实**：原版底层只有饮用（Drinking）带有 `item:isTaintedWater()` 的生水才会引发健康扣减与中毒。调用 `ISWashClothing` 与 `ISWashYourself` 时，使用任何生水水源（雨水桶、水坑）均完全安全，不造成任何生理伤害。
* **对齐规范**：
  * 饮用与烹饪入菜严格强制使用过滤纯净水（Plumbed Sink 或纯净水瓶）；
  * 清洗身体血迹与衣物污垢允许就近取用雨水桶未过滤生水，禁止因为洗衣服而过度挤占宝贵的饮用净水。

### 2.5 发电机维保：严格绑定 `ElectronicsMag4` 知识与 `ElectronicsScrap` 材料

* **错误设计假设**：工匠消耗废金属/电子元件修理发电机，燃油低时直接加油。
* **引擎物理事实**：原版 `ISRepairGenerator.lua` 明确只消耗 `Base.ElectronicsScrap`（电子零件），不消耗废金属；且任何角色操作发电机（维修、加油、接线）必须具备【电工】职业或掌握【发电机使用指南（`ElectronicsMag4`）】配方。
* **对齐规范**：
  * 只有已读完 `ElectronicsMag4` 或自带电工特质的工匠才能认领发电机巡检与加油任务；
  * 检修材料严格锁定为电子零件（`ElectronicsScrap`），杜绝扣减金属加工材料。

### 2.6 枪械与战斗：纳入原版“卡壳排障”与“弹匣装退”完整闭环

* **错误设计假设**：枪械像冷兵器一样只有耐久度下降，耐久低时回库换枪；只提消耗子弹，不提枪械机械状态。
* **引擎物理事实**：枪械最大的失能风险是**卡壳（`weapon:isJammed()`）**，且大多数枪械依赖弹匣（`containsClip`）与拉栓上膛。
* **对齐规范**：
  * 战斗 AI 射击前必须检查并处理卡壳：触发 `isJammed()` 时，立即执行拉栓排障动作（`ISRackFirearm`）；
  * 换弹逻辑必须涵盖弹匣：背包备有装满的弹匣时执行 `ISInsertMagazine`；脱战后自主将散装子弹压入空弹匣（`ISLoadBulletsIntoMagazine`）。

### 2.7 狭窄走廊避让：1-tile 门框软相位穿透（Soft Phasing）

* **错误设计假设**：在狭窄单格通道中要求“100%保留物理刚体碰撞”且“完全依靠步行动作侧身让路”。
* **引擎物理事实**：PZ 是 1x1 网格化地图。门框仅有 1 格宽度，两侧均为不可通行的实心墙。两人在 1-tile 空间迎面相遇时，底层 Java 物理引擎毫秒级触发 `bump` 碰撞阻挡，不存在任何侧移空间。
* **对齐规范**：
  * 随从与玩家在单格过道/门框相迎时，随从优先后退；
  * 当检测到玩家持续向前挤压且无后退网格时，临时赋予随从**软接触穿透（Soft Phasing）**，允许玩家平滑穿过，彻底消除门框卡死与无限推挤。

## 3. 约束与后续实施映射

1. **P2 个人生活闭环**：
   * 自我照顾直接调用就地止血（撕布条包扎），不依赖医务室工单；
   * 水利调用直接允许雨水桶洗涤；
   * 读书严格走 `ISReadABook` 物理翻页。
2. **P4 烹饪与设施**：
   * 烹饪任务按冷配方 + `IsoStove` 容器热模拟双阶段建模。
3. **P5 战备与专业工种**：
   * 医疗划分为止血自救与诊所高阶治疗；
   * 发电机维保核验 `ElectronicsMag4`；
   * 哨卫射击包含排障（Rack）与弹匣管理。
