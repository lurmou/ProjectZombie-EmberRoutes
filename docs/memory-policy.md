# Hindsight 项目知识收录规则

日期：2026-10-19。适用：EmberRoutes。用户要求清除旧AI记忆，并制定可信收录规则。

## 定位与依据

仓库文档、当前代码、对应版本引擎资料和实机证据是正式依据。Hindsight保存简短知识摘要和来源索引，帮助跨会话检索，不能单独作为实现或验收证据。检索结论用于修改代码前须回查来源；引擎版本变化后须复核受影响结论。

当前需求与明确决定优先于旧需求；同一主题以有来源的最新适用结论为准。HANDOFF和BACKLOG含历史待测记录，不能全文抽取后把每条都视为当前事实。

## 可以收录

- 用户明确的长期需求、偏好、范围边界及其日期。
- 已确定的设计决定、理由、适用范围和否决方案。
- 经代码或对应版本引擎资料核实的约束；已定位的问题根因和修复。
- 有证据的验收结果，分别注明本地检查、用户实测反馈、直接日志、故障恢复、MP及性能测试的实际覆盖。
- 当前未解决的关键限制，但必须明确标为未验证、待办或假设，不能写成事实或承诺。

## 不收录

- 旧AI记忆、旧对话、提交消息、代码调查报告的无审核批量导入。
- 命令流水、文件读写、聊天寒暄、重复进度播报和工具部署过程。
- 无出处的API判断、未运行的测试、未经确认的根因和“所有功能完成”等泛化结论。
- 密钥、令牌、凭据、完整私人对话和与项目无关的个人信息。
- 原始大日志、源码全文、重复副本；使用仓库内证据路径代替。

## 每条知识格式

每条聚焦一个主题，使用稳定主题标识；记录以下字段：

| 字段 | 要求 |
|---|---|
| 主题与结论 | 简明、具体；不扩张来源的结论 |
| 日期与版本 | 模组版本；涉及引擎时注明游戏/ZombieBuddy版本或基线文档 |
| 状态 | 已决定／代码核实／本地检查通过／用户反馈通过／日志直接确认／未验证／已废弃，可并列但不混同 |
| 来源 | 仓库相对路径及章节或符号；测试注明日志/报告位置；用户决定先落入仓库文档 |
| 边界 | 未覆盖的情境、已知限制、是否适用于SP/MP |
| 替代关系 | 修改旧结论时注明被替代主题与原因 |

示例：0.5.3正常单人保存/恢复主流程获用户通过反馈；日志直接确认同UUID/三物品恢复及删除后空记录重进；第9步距离门禁依用户反馈，第11步样本清理未确认。来源：reviews/2026-10-19/probe-0.5.3-runtime.md。不能改写为“完整NPC状态已验证、崩溃无损”。

## 写入、更新与启用

1. 先完成调查并把决定/证据写入对应仓库文档，再整理摘要；不逐轮自动保存整段对话。
2. 写入前检查来源存在、版本适用、验证层级明确、不含凭据，并排除重复或已被替代内容。常规已核实摘要不要求用户逐条批准。
3. 错误记忆必须更正或移除，注明正确结论及证据；不只追加互相冲突的摘要。废弃决定保留历史身份，不继续作为当前方案召回。
4. 关闭自动对话回写及历史导入、Git导入、首次自动播种和代码调查；自动注入关闭，按需检索。提取提示词只能辅助，不能替代上述写入筛选。
5. 仅使用EmberRoutes独立库，禁止与其他项目混库。用户随后已要求启用：当前disabled=false、optInOnly=true，仅本项目路径映射到coding-agent::EmberRoutes独立库。自动导入与自动注入保持关闭，未导入旧资料。用户随后授权收录长期架构要求，已人工整理一份带来源的摘要，详见development-rules.md；不再是空库。当前会话未暴露Hindsight专用工具，配置启用不等于长期客户端已重载。
6. 首批可整理AGENTS、development-rules、当前SP优先决定及最新验收记录；HANDOFF/BACKLOG只摘当前有效结论。不恢复被删除的旧库。

## 本轮清理范围

此前删除projectZombie库，服务端返回成功及3860条关联数据删除；2026-10-19本轮再次查询banks，total=0。此结论仅表示当前服务端API所见记忆库已清空，不是磁盘安全擦除证明。

插件诊断日志、原始聊天、服务配置、模型文件及项目资料不属于记忆库，未删除；不会将其自动导回。随后按用户要求启用集成并创建EmberRoutes独立空库，显式关闭各自动导入入口。已运行的长期客户端可能仍持有旧配置或上下文，重新启用前应重启相关客户端；删除服务器记忆不会擦除现有聊天上下文。
