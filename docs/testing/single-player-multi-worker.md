# 0.12.0 多 NPC 内核集中实测

日期：2026-10-20；状态：本地逻辑/真实 Kahlua 检查与游戏实测分开记录，本轮游戏实测待验。

完整退出游戏后重新启动，使 ZombieBuddy 加载 **0.12.0** Java/Lua。沿用原存档和 NPC 即可；先在安全、已加载的区域测试。两个端点和 NPC 之间保持约 16 格以内，这是当前载体原型的移动门禁。物品仍用原实例；每单上限 30 件。

1. **旧存档与第二人。** 先检查原 NPC 和物品能否恢复。在世界右键的模组菜单进入“选择 NPC”，选择“生成另一名 NPC”。列表以稳定 ID 前八位区分，圆点表示当前选中者。分别选中并使用“检查”“移动到此处”，确认指令对应两个不同的人。旧“生成 NPC”仍用于首人，已有当前 NPC 时不会替换他。
2. **两条独立路线。** 准备两组源箱/目标箱，放入不同、未收藏且符合目标筛选的普通物品。选 A，设置 A 的源/目标并开始搬运；再选 B，设置另一条路线并开始。两人应同时工作，切换选择不应改变 A 的路线；各自“工单报告”应有不同 task/npc ID 和正确数量。可同时打开仓储确认物品变化与既有搜索、脏行更新。
3. **同一物品争用。** 在空闲的 A/B 上设置同一源箱。先给 A 开单，再让 B 开单：若没有未认领的物品，B 应提示“物品已被其他工单预留”。此时向源箱增加另一件物品，B 可为新物品开单；不应认领或复制 A 的原物品。
4. **独立暂停与随从。** 两人工作时暂停 A，B 应继续。对 A 发跟随/原地待命，B 的搬运不受影响；A 原工单暂停后可选 A 续工。反过来也测一次。持货的暂停工单不能清除或删除 NPC；先续工把货交到目标，再清除。
5. **容量争用。** 用两组不同源箱指向同一个目标，留出仅够一件同重量物品的空间。A 拿货后暂停；B 的货应留在源箱，报告可显示“等待目标容器的预留空间”。A 续工交付后，若箱子实际已满，B 应暂停并说明目标已满；腾出真实空间后对 B 续工。玩家/其他模组仍可改容器，预留不会锁住原版库存操作。
6. **搬运中保存、退出与恢复。** 两人同时工作，尽量让一人持货、一人未拿货，使用现有“保存世界”再退出。重进后两名 NPC 应保持各自 ID、原物品状态和各自工单；工单暂停，分别续工。自动恢复每帧只尝试一个记录，不会反复重试。若某人原位置未加载或离玩家超过 16 格，在“选择 NPC”选他的 ID，接近原位置后点击“重试恢复”；不要新建替代人来代替恢复。
7. **删除隔离与旧功能。** 无任务货物时删除 A，B 的路线/随从应继续；保存重进后 A 不应复活，B 仍应恢复。再测原来的上楼移动、仓储筛选、搜索和来源定位。诊断动作/17 步搬运仍是单批次测试夹具；若提示 `FIXTURE_OTHER_NPC`，切回夹具拥有者清理后再给另一人运行。

请保留本次 `BOOT`、`WORK STATE/WAIT/REPORT/ITEM`、`PERSISTENCE SAVE/AUTO`、`CHECKPOINT_*`、`MOVE_*` 及报错附近日志。无法判断位置时先打印两人的工单和检查点报告，不要删除持货 NPC。

本轮没有自动多仓分拣、工种/优先级派工、完整效用 AI、死亡货物自动转单或联机实现。大规模 NPC、真实并发动作兼容和跨文件崩溃一致性未验证；逻辑预算检查不等于实机帧率结论。
