# 0.3.0 实体容器搬运：一次会话测试

> 日期：2026-10-19｜状态：17步SP主流程已实机通过；异常场景待逐项验证

最新结果见 [0.3.0 实机记录](../reviews/2026-10-19/probe-0.3.0-runtime.md)，下方保留完整操作与补测步骤。

当前0.4.0整包保留相同测试菜单；从 [随从测试](single-player-companion.md) 回归时使用当前整包，不必回退0.3.0。下方版本号是原始0.3.0验收步骤。

0.2.0 的十项吃喝/背包动作已由用户和日志确认通过，见 [实机记录](../reviews/2026-10-19/probe-0.2.0-runtime.md)。本包保留旧测试，新增源箱—NPC—目标箱—NPC—源箱的 17 步闭环。

## 准备和主流程

1. 完整退出游戏，使用 0.3.0 整包，确认 BOOT 与 READY 都是 `v0.3.0`；安装与沙盒开关见 [载体说明](phase0-carrier.md)。只装一个副本，仍用临时单机世界、正常 1 倍速，关闭瞬间动作。
2. 准备两个**现有世界容器**，例如地面木箱、柜子、货架。两个容器和 NPC 最好在玩家附近 8 格内，先用同层、无遮挡、留有余量的两个箱子。暂不支持地面物品、背包、尸体、车辆或冰箱的第二子容器；不要用有重要物资的正式存档。
3. 站在源箱旁，右键箱子 → 载体探针 → **实体容器搬运测试 → 指定点击的容器（类型及坐标）→ 标记为测试源箱**。到另一个箱子旁，同样标记“测试目标箱”。两者必须不同；标记时须贴近同层容器。
4. 生成并停止一个健康 NPC。右键 → **实体容器搬运测试 → 运行三件物品往返测试（17步）**。
5. 测试会在源箱生成一支铅笔、一把螺丝刀、一把勺子。NPC 接近源箱，逐件取入主背包，步行到目标箱，逐件存入，再原样带回源箱。每次转移核对同一实例、ID、耐久、名称、ModData 和三个容器中的唯一性。不会搬动箱内原有物资。
6. 等待 `PASSED 17`；点击“打印搬运报告与物品位置”。查看 `console.txt` 中 `[EmberRoutes v0.3.0] HAUL` 行。完整流程通常需一两分钟，取决于路径与动作速度；每次路径最多 20 秒，步骤总超时 60 秒现实时间。

17 步 = 往程两次接近 + 六次转移，返程两次接近 + 六次转移，最后观察两秒不重复结算。走到容器旁不等于转移完成，必须看原版动作与实际库存。

## 同一会话补测

| 情境 | 操作 | 预期 |
|---|---|---|
| 重复命令 | 工作中再次运行；尝试旧吃喝测试 | 返回 BUSY，不再生成三件物资，不抢占执行 |
| 正在步行/搬运时取消 | 点击“取消搬运” | 停止路径和动作；已完成的转移保留当前位置，不能报告整个任务通过 |
| 外部指令中断 | 工作中使用旧“移动到此处”或“停止” | 先取消搬运，再执行新指令；后续转移不继续 |
| 标签失效 | 工作中到目标箱旁解除其测试标签 | 下一次检查取消任务，物品留在当前实际容器；重新标记后可重测 |
| 容量不足 | 主流程通过后，将目标箱装满，再运行 | 出现 DESTINATION_FULL 的 ERROR/取消，不能强行塞入或复制；查看 ITEM_LOCATION 后清理夹具 |
| 路径受阻 | 将箱子隔在无法到达的房间；或合适楼梯上下层 | 无路明确失败/超时；有路时须真正走到可触及位置后才搬运，不隔墙/跨层远程拿取 |
| 容器变化 | 工作中搬走/拆除测试箱 | 当前绑定失效即取消；本项是诊断场景，先保证箱中没有正式资产 |
| 再次执行 | 取消/失败后查看报告，再清理夹具、重新运行 | 上一批不会自动继续；只清理该批三件原物品，然后建立新批次 |

清理只针对本次三个物品引用；若物品进入未知容器或身份/状态发生变化，返回 CLEANUP_BLOCKED，保留证据，不按类型重建。不要手动拿走、改名或使用这些测试工具，除非专门验证阻塞。

## 结束与边界

清理测试物资，解除测试标签，点击“移除”并**等到 REMOVED / carrier=absent 后再保存退出**。0.2.0 的退出日志只有 REMOVAL_PENDING，保存退场尚未完整验收；本包没有宣称解决任意保存顺序、死亡掉落或崩溃恢复。

本包容器使用稳定 UUID，并在每次转移前复查当前角色标签、对象仍在世界、仍是原容器、区块已加载、当前位置可触及和容量。只操作显式指定的两个容器及本次夹具；不扫描未标记私人仓库。

仍为 SP 探针；多人不生成/操作 NPC。容器标签是当前诊断会话绑定，不是已完成的领地权限或跨重启经营账本。下一关键关口仍为专服驱动与同步验证。
