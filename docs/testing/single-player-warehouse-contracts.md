# 0.9.0 仓储基础设施合并复测

日期2026-10-20；新实机待测。用户已确认0.8.2提示虚影修复成功，本轮保留该修复，不改视觉样式。完整退出重启确认EmberRoutes v0.9.0；可沿用原世界、据点、容器规则与NPC，无需重建旧探针。包见[0.9.0](../../build/packages/EmberRoutesProbe-0.9.0.zip)。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 原存档进入据点，打开仓储，搜索已知物品并点来源 | 原据点/旧箱子配置还在；数量、楼层正确；开关数次不残留tooltip。日志一轮WAREHOUSE READY，含加载/未知/私有等计数 |
| 2 | 冰箱主格和冰柜各放少量易辨认物品、分别配置不同过滤规则；刷新查看 | 分别登记、来源名称区分，物品不混算；再正常保存重进，规则与来源保留。没有冰箱可仅测两个箱子，冰柜项记未测 |
| 3 | NPC货物清空后，按已有操作把少量允许食品从源箱搬入冰柜或目标箱；观察仓储 | 转移期间旧数量撤下；NPC身上的物品不计仓储；交付后来源正确，原任务仍能连续派单。没有可用NPC可记录未测，不重建所有探针 |
| 4 | 改私人/停用，再恢复；玩家手动取放后点击刷新 | 私有库存不读，恢复后正确；手工操作仍显式刷新。遇到持续变动提示时等搬运结束再刷新，应能恢复，不显示旧候选冒充当前库存 |
| 5 | 若已有较多库存，打开或暂停时刷新盘点，等待更新结束；更新中关闭再打开 | 允许分片显示更新中；游戏操作仍可响应，关闭取消，重开正确。无需为了压测制造两万物品；大规模帧耗没测就记未测 |
| 6 | 正常保存退出重进，重新打开仓储；若自然遇到原箱卸载/拆除，再点刷新 | 新盘点重建当前物理端点；卸载/失效有计数，不保留旧货。保存不是强退原子性验证，无需破坏贵重容器制造故障 |

反馈失败步骤、现象即可，console.txt无需清空。查询接口在逻辑和真实Kahlua检查，不要求用户在游戏控制台调用内部API；本轮UI仍是验证版。API、算法与边界见[架构](../settlement-storage-architecture.md)，验证见[记录](../reviews/2026-10-20/probe-0.9.0-warehouse-contracts.md)。
