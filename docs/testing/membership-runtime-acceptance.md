# 驻扎模型集中单人验收（0.27.0）

> 状态：未运行。宿主与构建结果见[开发证据及闲暇交接](../reviews/2026-10-25/npc-settlement-membership.md)。不在旧档验证升级，不需要删除旧存档。

## 准备

使用0.27.0匹配的Lua与Java包，新建测试世界。通过现有Debug入口生成2名NPC，登记两个据点；在各据点地面右键本模组随从菜单设置返回点。配置少量食物、水、实体书及可完成制作/搬运的分类仓储，沿用已有规则，不额外制造大量样本。

## 一次连续流程

1. 人员页应能看到未分配NPC；在人员详情菜单或右键随从菜单将两人驻扎于A。显示“据点A｜驻扎生活”，新普通工单和闲暇只取A的资源。
2. 带一人跟随走入B或重叠区，确认仍属于A、停止领取普通据点工作；命令原地等待后不自主闲逛。必要吃喝仍可发生，跟随时不擅自绕回基地取共享物资。
3. 圈外命令返回A，观察正常走回并恢复驻扎；删除/阻挡返回点或让目标未加载时，应显示具体原因、等待重试，无传送、无假报到达、无密集重复寻路日志。
4. 让一人借书或取到搬运原件后调驻B。交接前仍显示A和待处理目标，并展示未还物品/携货明细；完成原责任后才改为B。取消待处理调驻应保留A，迟到的旧回调不能再把他调走。逐个核对原件，没有按类型补造。
5. 在研习/闲暇、社交邀请未接受时切跟随/等待；旧邀请不能被接受或启动旧活动，停止/归还后再释放设施和物品。WAIT再切驻扎应能恢复已有责任，不因旧暂停记录一直罚站。
6. 待处理交接、返回途中、借书待还分别正常保存退出再进：先恢复身份/责任，再恢复唯一执行；重复命令不二次搬物或授予收益。
7. 保留一名跟随者，测试玩家死亡与新角色：据点和NPC归属仍在，旧跟随目标失效，新角色重新下令后才跟随。另测NPC死亡，未结原件责任保留；确认结清的记录可以回收。
