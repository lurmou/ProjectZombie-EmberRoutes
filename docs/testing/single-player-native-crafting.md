# 单人制作原型：分类仓储与通用表面

> 本页保留0.17.1历史诊断原型步骤。当前0.18.0正式制作及续工请看[单件制作与续工](single-player-crafting-orders.md)。用户已确认0.17.3正常制作成功。

> 2026-10-21｜0.17.1｜状态：待实机验证｜[修正记录](../reviews/2026-10-21/probe-0.17.1-classified-crafting.md)

直接复用现有据点和储物箱分类设置，不新增“生产专用箱”配置。NPC从匹配分类的共享箱取材料/工具，在原版允许的通用表面制作一把木叉，再把木叉和原工具分别送回匹配分类箱。新单不会从玩家背包取料，缺料时也不会回退到玩家身上。

## 准备一次

使用单人开发存档，启用Debug与载体探针，选择现有NPC。玩家与NPC在同一有权限的据点，玩家已掌握木叉配方，NPC雕刻至少2级且健康至少95。NPC有空余负重，取料/交付路径可达。

沿用当前箱子登记和过滤规则即可：木柄所在分类箱允许`Base.SmallHandle`，刀具分类箱允许那把锋利刀，成品分类箱允许`Base.WoodenFork`；箱子应共享、参与STORAGE，不能为私人或物流排除箱。可以是不同箱，也可以是现有规则允许的同一箱。只看各箱主容器，不搜索包中包；收藏、装备或诊断样本等原有受保护物品不参与。

据点里准备原版判定可作为制作表面的普通桌面/平台；**无需砧板或CraftBench组件**。不是所有外观平整的家具都算，最终沿用原版表面判定。NPC会复用已有移动逻辑前往箱子和表面，玩家无需一直站在NPC旁，但本原型运行时仍需留在该据点内。

没有达标NPC的开发存档，可由用户在原版Lua控制台显式准备一次样本；模组不自动提升技能或治疗，这也不代表训练系统已经实现：

```lua
local n = EmberRoutesProbeJava.carrierFor(EmberRoutesProbeJava.selectedId(), getPlayer())
if n then n:setPerkLevelDebug(Perks.Carving, 2) end
```

## 三组必要操作

1. **正常分类取还**：右键可用平台 → 原版Debug → 余烬商路诊断 → 原版制作原型。必要时先显式传授木叉配方，再选“试制一把木叉（分类仓储取料）”。应看到NPC取木柄/刀、到平台制作、把1把木叉送入匹配成品箱，并把同一把刀归还匹配分类箱；刀可能正常磨损，玩家物品不应变化。NPC原有的可用工具也会在完成后分类归还，不默认留在身上。报告最后应为DONE。
2. **缺料与中断**：材料箱缺木柄而玩家背包有木柄时，仍应提示缺料。取料后、制作提交前停止，再选择“归还原件／恢复携货”；未消耗原材料及工具应回到对应分类箱。私人/排除箱不可作为来源；无匹配交付箱或满箱时暂停保留原件，调整现有分类规则后显式恢复，不应再制作一件。
3. **正常保存重进**：取料或制作途中保存退出，重进后查看报告；应暂停、不自动重做。选择“归还原件／恢复携货”，未制作返回原料，已确认制作则交付原产物和工具。待处理原件应阻止该NPC重新接物流单或被删除，其他NPC仍可工作。

完成诊断后若要恢复该NPC的自动物流，在原物流页重新启用即可。不要重跑历史全套测试。

出现`RECONCILE_REQUIRED`时保留CRAFT日志，不重复下单。落地原产物可正常收回到同据点共享分类箱，再显式恢复；证据不足的消耗后异常继续阻断，不补材料、不凭类型造产物。旧0.17.0玩家借用记录仅保留显式归还兼容，新单不使用该路径。强退崩溃恢复、完整BOM和正式制作页仍未验证或实现。
