## 建议按顺序一次完成

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 生成一个 NPC，选择“准备可跨存档验收样本”，再点一次准备；选择“核对样本”和“打印状态与物品 ID” | `SAMPLE_PREPARED`、再次 `SAMPLE_EXISTS`；核对 `SAMPLE_PASSED`，记录 NPC UUID 以及三个物品 ID |
| 2 | 在一楼或二楼设置驻点，命令跟随；选择“正常保存整个世界（不退出）”，随后走动几格 | `CHECKPOINT_SAVED`；NPC 继续跟随。人物没有被保存操作删掉，驻点没有丢失 |
| 3 | 人物存在时连续两次“重试恢复”，再点一次“在此生成” | 恢复为 `RESTORE_ALREADY_CONSUMED`，生成为 `EXISTS`；始终只有一个 NPC |
| 4 | 原有十项动作、两容器十七步搬运各跑一轮，之后再核对存档样本 | 旧批次通过；样本仍是原 ID，嵌套水瓶、名称、铅笔耐久和手持关系正确。动作/搬运夹具与存档样本分开管理 |
| 5 | 再开始搬运，途中点击“正常保存整个世界（不退出）” | 搬运取消，原版动作队列清空，夹具回收；保存为 HOLD，不在存档后重做半截转移；样本核对通过 |
| 6 | 重新跟随，正常退出到主菜单，再载入同一世界 | 自动恢复一次，日志 `DISPOSED_WORLD_RELEASED`（同一 Java 类实例保留时）及 `CHECKPOINT_RESTORED`；UUID、物品 ID 不变，核对样本通过，继续跟随 |
| 7 | 选择“返回驻点”，再测试二楼到一楼/一楼到二楼的近距离路径 | 使用原驻点和新建路径，到达后待命；没有重放旧动作队列 |
| 8 | 保存、完整退出游戏、重新启动并载入同一世界，再次核对样本和重复恢复 | 自动出现一个相同 UUID 的人物；`SAMPLE_PASSED`，手持物、外观和身体情况符合保存前观察；重复恢复仍被拒绝 |
| 9 | 待命后让玩家离开约20格（不要离开加载区），正常保存并退出到主菜单，再载入 | 可能为 `RESTORE_TOO_FAR`；尝试生成应为 `CHECKPOINT_PENDING`。根据日志原坐标靠近到16格内，再“重试恢复”，应恢复原人物及样本，不瞬移到玩家旁边 |
| 10 | A世界保留NPC并正常保存退出，载入开启探针的空B世界；再退出并返回A世界 | B世界 `CHECKPOINT_EMPTY`，不带入A人物；回A后恢复A的UUID与样本 |
| 11 | “清理验收样本”，核对背包只移除这三个测试实例；如把样本包装在身上，先卸下再清理 | `SAMPLE_CLEANED`；其他物品不受影响；重复准备不会累加旧样本 |
| 12 | 删除NPC，等待 `REMOVED`；正常保存、退出并重进 | `CHECKPOINT_EMPTY`，不从旧快照复活。此后可以生成新UUID的人物 |

样本是一只测试书包、一支改名且降低耐久的铅笔、一瓶嵌套在包内的水。原主手为空时会手持铅笔；已有手持物不会被覆盖。样本检查自动比较 ID、父容器、名称、耐久、自定义标记、水量和原主手关系。身体健康前后值会打印，但自然流逝可能改变数值，不能据单次样本通过宣称所有身体/技能状态都已实机验证。装备与技能的更广覆盖仍需后续专项结果。

## 失败时的预期

`CHECKPOINT_BLOCKED` 表示本轮NPC检查点未成功；会显示提示，先保留日志、解除夹具或角色状态阻塞，再正常保存。退出前没解除，下一次会拒绝恢复旧人物，不能声称没有损失。着火、乘车、版本/校验和不符、物品脚本缺失、物品ID/装备不一致、超出大小限制都不能静默恢复。

`RESTORE_TILE_UNAVAILABLE` / `RESTORE_TOO_FAR` 会保留现有记录，只自动尝试一次；到原位置再显式重试。`BASELINE_CHANGED` / `BASELINE_UNAVAILABLE` 拒绝驱动，先保留启动日志。引擎未完成旧世界销毁时 `RESET_REQUIRED` / `REMOVAL_BLOCKED` 会阻塞，不能强拆旧世界对象；保留日志后完整重启游戏。

损坏、截断、缺块/错序、旧版本、跨世界、重复ID、循环容器、超限与旧快照重放已有纯逻辑测试；本轮不要求手改游戏二进制存档。存档与玩家、物品和世界文件存在共同时间点要求；备份/恢复须覆盖整个世界目录，不能只回滚 `global_mod_data.bin`。当前世界路径也参与检查，不支持靠重命名存档目录自动迁移人物。

技术说明见 [0.5.0记录](../reviews/2026-10-19/probe-0.5.0-persistence.md)。测试后正常保留日志即可，默认筛选 `[EmberRoutes v0.5.3]`，无需清空整个游戏日志。
