# 0.15.1 容器配置与物流管理使用说明

日期2026-10-21；状态：0.15.1启动/关闭修复与紧凑视觉待确认。本轮只需按原配置打开、启动、关闭物流页，观察错误与模式框；下方十项是按需排查清单，不要求重跑。

完整退出游戏后重启，确认0.15.1配套Lua/Java。使用已有据点，NPC和测试容器都放在范围内、已加载且路径可达。正式功能在右键“余烬商路”；生成/删除NPC、动作套件、测试样本、旧17步搬运和保存诊断在原版“Debug → 余烬商路诊断”，非Debug模式不可见。

## 一次性配置

1. 世界右键“余烬商路 → 容器设置 → 此容器”，或右键物品栏侧边容器图标“容器设置”。进入“仓储用途与物品筛选”，在用途组合框选“分类仓库”，选食品/工具/医疗等预设或自行勾选类别，启用且不私有，点击原版“应用”。
2. 给杂物箱在同一编辑器选择“入库/卸货箱”，点击“应用”。入库箱只供货，不必勾选接收规则；目标箱保持“分类仓库”，不能把所有箱都设为入库。复制/粘贴只替换允许/排除规则，保留目标的用途与私人/停用开关；进入草稿后仍需应用。取消不改世界，跨世界须重新复制。
3. 在据点内右键“余烬商路 → 据点物流管理 - 据点名”打开统一窗口，点击“加入空闲NPC”，勾选入库/错放模式，再“启动物流”。左侧选中工人，右侧查看交付数、工单、来源/目标和原因；可独立重试或移出，不影响其他工人。已有手动未完成工单或跟随中的NPC不会被抢走；先结束旧任务或待命，也可将游戏当前选中NPC明确加入。

等待原因直接显示在管理页：目标无允许规则、缺少分类仓库/入库箱、源空、物品已归位或受保护、没有匹配目标、容量不足，以及被旧手动任务占用。旧手动任务先续工；确认没有携货才清除。0.16.0起仓储/物流为同一据点窗口的两个页签；顶部页签或物流页的仓储按钮直接切页。PageUp/PageDown切页，手柄在两栏外侧按方向键切页。关闭不停止物流，隐藏仓储停止该页盘点订阅，返回可能重新盘点。此次仅需日常观察切页、关闭重开和NPC继续工作，下方历史合并清单无需重复全跑。

0.16.1日常确认：同一批交付时数量应递增，取货转交付时文字应改变；换新批次显示新的编号/总数，并保留“上批已完成6/6”等摘要。摘要仅本次世界会话最近一条，不是历史报表；不需要为本补丁重复下方历史全套。

## 合并验收

1. **混合入库。** 将食品、工具、医疗等放进入库箱。两个NPC应自动领取不同批次，送往符合规则的仓库；新加一批物品后无需手动开新单。
2. **一趟多件。** 放至少5件较轻的同类物品，保证NPC和目标空间足够。应连续装入多件，再走向目标连续卸下；不是拿一件就往返。单批按角色剩余负重、库存和目标容量取较小值，最多30件；重物可能只能每趟一件。原版动作仍逐件执行，批次不等于瞬间整箱转移。
3. **错放整理与稳定。** 把食品直接放进只允许工具的已标记仓库，应被移到食品仓库。正确食品仓库里的食品保持原位。多次等待、重新扫描后，不应在两个都接受食品的仓库之间来回搬。
4. **规则精度与容量。** 准备一个宽泛食品仓库和一个明确fullType例外的目标，同一物品应优先明确规则；同精度使用较近目标，最后按稳定ID。填满该目标，再投入新货，应该寻找其他合适空位。没有目标/所有目标满时货留原位；取出腾空后应在后续扫描中继续。扫描/规则缓存有短暂延迟，不要求当帧响应。
5. **私有与保护。** 未标记箱、私有箱、停用箱和物流排除箱不能被拿取；收藏、装备、包容器及验证夹具不搬。将一个已共享容器改为私有，应阻止后续效果，持有货物保留，不强行删除任务。冰箱和冰柜各格配置独立。
6. **多人/人工接管。** 两名NPC同时工作，手动移动、暂停或让A跟随，A不应立即被自动任务抢回，B继续工作。需要A重新参加时先待命，在据点停止后重新启动一次物流。退出当前NPC物流只影响该人，不清除其持货。
7. **途中变化。** A装了一部分货时改变源筛选使剩余物品不再错放，已持有且仍有合法目标的货先交付，其余保持原位。若目标变私有/卸载/规则拒收，任务应暂停并保留原货；不要自动清除货物账。恢复合法配置后从据点停止/启动或检查工单后续工。
8. **保存与重进。** 两人工作，其中一人已装多件时保存不退出，检查保存后能继续原批次。再保存退出重进：模式/名单/容器用途应还在，物流会话默认停止；在据点启动一次，持货的原批次按同NPC/物品ID继续，不重新认领/复制。未加载的NPC仍须按原检查点说明接近原位置恢复。
9. **较远及二楼路线。** 让源/目标相距约25–40格但均已加载，或目标在可达二楼；按ID工作的移动可超过旧16格诊断门禁。寻路/加载失败应有明确暂停，不瞬移、不持续重新发同一失败路径。恢复出生点仍须接近16格。
10. **停止与旧UI。** 据点停止后所有自动动作应停下，持货留下；重新启动恢复。仓储搜索、筛选、定位、稳定行更新仍应正常。状态菜单会记录各工人task/npc/state/reason；旧显式路线仍可单独使用。

日志保留 `LOGISTICS START/STOP/POOL/REPORT/WORKER`、`WORK STATE/TRANSFER/WAIT`、`PERSISTENCE`、`CHECKPOINT_*`、`MOVE_*` 和报错前后。无任务时SCANNING/NO_ROUTE是低频等候，报告说明不是完整经营AI。没有实际启动游戏则不能记本表通过。

当前仅已登记容器直接物品，不包含包内、地面拾取、未加载/离线物流或自动生产。路径失败/超时/受伤等需明确处理或停止/重新启动，不无限自动撞墙；已拿货物不会通过删除重造补偿。规模性能、联机和跨世界文件崩溃原子性未验证。
